## 1. Fault Handling — วิธีคิดที่อาจารย์เน้นก่อนเข้าเรื่อง masking

- **ลำดับการคิดที่อาจารย์ย้ำ:** ก่อนจะป้องกันอะไรได้ ต้อง **model fault ให้ได้ก่อน** ว่า fault ที่เราจัดการเป็นประเภทไหน → แล้วค่อยเลือกวิธี
- ทางแยกสองทางหลัก:
  - **Avoid (หลีกเลี่ยง)** = พยายาม "ไม่ให้เกิด" — ทำได้ถึงระดับหนึ่งด้วย **quality assurance** ที่คอยปิดจุดอ่อน/ช่องโหว่ให้หมด ("ดูจุดที่ทำให้เราอ่อน แล้วปิดจุดนั้นให้หมด")
  - **Tolerate (ยอมให้เกิด)** = ยอมให้เกิด แต่จัดการได้ — ใช้แนวคิดจาก **testing**: ตั้ง test model บนพื้นฐานของ **fault model** แล้วทำการ **remove** (ซ่อมได้ = Repair / ซ่อมไม่ได้ = Discard)
- อีกเส้นทางของ Tolerate = ** redundancy**: ใช้ **Dynamic Redundancy + Monitor** เพื่อ **Expose** fault ออกมา แล้วตัดสินใจ:
  - ทำงานต่อโดยยอมเสียบางส่วน **แต่ปลอดภัย** = **Fail-safe**
  - **Degraded** (บริการลดหลั่น)
  - หรือ **Restore** (กู้คืน)
- **คำจำกัดความสามชั้นที่อาจารย์กางออกมาให้เห็นภาพ (สไลด์ 6):**
  - **Fault Avoidance** = กันไม่ให้ hardware/software fault ผลิตการทำงานที่ผิดพลาดขึ้นมาตั้งแต่ต้น
  - **Fault Masking** = เมื่อ fault เกิดแล้ว "กันไม่ให้กลายเป็น error แล้วลุกลามออกไป" (กดไว้ที่ชั้นนี้)
  - ถ้า masking ไม่ผ่าน → ถึงอีกระดับหนึ่งจึงกลายเป็น **failure** (ชั้น Fault Tolerance)
- `[ไม่แน่ใจ: อาจารย์พูดถึงสไลด์ 7 ว่าอันบนสุดเป็น "ธรรมชาติ/ลักษณะของ redundancy" — น่าจะเป็นการแยก 3 แบบ: detect&replace (dynamic), mask (static), hybrid]`

## 2. Inherent / Logic Masking (สไลด์ 10–11)

- **แก่นที่อาจารย์ปู:** fault เดียวกัน อาจเป็น **critical** หรือ **non-critical** ได้ ขึ้นกับ *ค่าที่ป้อนอยู่* ตอนนั้น
- ตัวอย่างที่ไล่ให้ดู (สไลด์ 10): ให้ `a b c d = 1 0 0 0` แล้วมี fault ที่ `b` เป็น **stuck-at-1**
  - ค่าที่ควรจะเป็นของ `b` คือ 0 → พอ stuck-at-1 ค่าเปลี่ยน 0→1 → ไล่ทำให้ค่าภายในเปลี่ยน → **มีผลถึง output → critical**
  - แต่ถ้าจุดนั้น "ควรเป็น 1 อยู่แล้ว" แล้ว stuck-at-1 → **ค่าไม่เปลี่ยน → ผลไม่ขยายไปยังเส้นภายในเลย → non-critical = ถูก mask ไปเอง**
- **Insight ที่อาจารย์เน้น:** ต่อให้เป็นวงจร **ธรรมดา (non-redundant)** ที่ไม่ได้จงใจทำ redundancy ก็ยังมี "ความสามารถกลืน fault" ในตัวอยู่บ้าง — เพราะเกตบางตัว/บางเส้นทาง ทำให้ error ไม่ลามออกไป
- เรียกว่า **Logic Mask** — เป็นกรณีของ **single fault / single error** ที่วิ่งเข้าไปในลอจิกแล้ว **ถูก mask จน output กลับมาถูกต้อง**
- นำไปสู่ไอเดียของ **AND-OR Logic Mask (สไลด์ 11)** — single error ถูก mask ได้ (NAND–NAND logic) `[ไม่แน่ใจ: รายละเอียดการไล่ค่า x1..x4/y1..y4]`

## 3. Interwoven Redundant Logic / Quadded Logic (สไลด์ 12–13)

- หลักการที่อาจารย์อธิบาย (สไลด์ 12):
  - **การเปลี่ยน 1→0 เป็น critical สำหรับ AND** แต่ถ้าเป็น OR จะเป็น subcritical
  - **การเปลี่ยน 0→1 เป็น critical สำหรับ OR** แต่ถ้าเป็น AND จะเป็น subcritical
  - ดังนั้น **การสลับชั้น AND / OR** ทำให้ "critical fault ของชั้นหนึ่ง ถูกกลืนโดยอีกชั้นหนึ่ง" (alternating layers mask each other's critical faults)
- การสร้างวงจร: เอา **signal x มาทำ 4 copies** (x1..x4) แล้วสร้างวงจรใหม่ที่ interwoven
- **ตัวเลขการขยายที่อาจารย์ทวน (ตรงสไลด์):**
  - **จำนวนเกต ×4** (ขยายเป็น 2 เท่า/4 เท่า — สไลด์ให้สูตร ×(h+1)² = 4 เมื่อ h=1)
  - **input ของเกต ×2** (ตามสไลด์ ×(h+1) = 2)
- **Quadded logic = เคส h = 1** (กลืน critical fault ได้ 1 ตัว)
- สไลด์ 13 (half-adder in quadded logic) — อาจารย์ยกเป็นตัวอย่างการนำไปใช้จริง ไม่ได้ไล่ทุกเกต

## 4. Combinatorial Modeling — Series / Parallel (สไลด์ 15–19)

- นิยามที่อาจารย์พูด: **แบ่งระบบเป็น module ที่ไม่ทับซ้อนกัน** แต่ละ module มีค่า `Pi` หรือ `Ri(t)`
- **สมมติฐานที่ต้องบอกให้ชัด (อาจารย์เน้น):** module **fail แบบ independent กัน** และเมื่อ fail แล้วให้ถือว่า **ให้ผลผิดตลอด**
- **Series:** ระบบต้องทำงานครบทุกตัว → `Rs = ∏Ri` ("R ของระบบ = ผลคูณของ component")
- **Parallel:** ใช้มุมกลับ → "ระบบทำงาน" = **ไม่ใช่กรณีที่ fail หมดทุกตัว** → `Rp = 1 − ∏(1 − Ri)`
- **ข้อสังเกตที่อาจารย์ชี้:** ค่า reliability ของ component ยิ่งดี ระบบก็ยิ่งดี; และเขาเน้นว่าสมมติฐาน **independence** เป็นเงื่อนไขสำคัญที่ทำให้ใช้สมการนี้ได้
- **ตัวอย่างการคำนวณ (สไลด์ 19)** ที่อาจารย์ไล่: ระบบผสม R1–R2 อนุกรม → กลุ่ม R3 ขนาน 3 ตัว → กลุ่ม R4 ขนาน 2 ตัว → R5 อนุกรม จึงค่อย ๆ ยุบทีละบล็อก (`[1-(1-R3)³]`, `[1-(1-R4)²]`, คูณ R5) `[ไม่แน่ใจ: ช่วง 00:33–00:36 อาจารย์พูดถึง "derivative ของ parallel" และค่าบางค่าที่ฟังไม่ชัด]`

## 5. Non-Series-Parallel System + **การแกะด้วย Keystone** (หัวใจของคาบ) (สไลด์ 20–32)

### 5.1 หลักการ (อาจารย์อธิบายเป็นภาษาคน)

- ระบบ **non-series-parallel** = ต่อยังไงก็ไม่ใช่ series และไม่ใช่ parallel ตรง ๆ → **ประเมิน reliability ตรง ๆ ไม่ได้**
- **แนวคิดตั้งต้น:** สมมติว่าเราต้องการให้ "ข้อมูล/การทำงานไหลจากซ้ายไปขวาตามลูกศร" ไปถึงปลายทางได้ครบ = ระบบทำงาน
- **วิธี (conditional decomposition):**
  1. **เลือก module `m` มาหนึ่งตัว**
  2. แยกเป็น **2 กรณี**: `m` **works** กับ `m` **fails**
  3. กรณีหนึ่ง ๆ จะ "ยุบ" วงจรให้ง่ายลง (ถ้ายัง non-series-parallel อยู่ ก็เลือก module ตัวต่อไป แล้วทำซ้ำ — เลือกวนไปเรื่อย ๆ จนจบ)
  4. รวมด้วยสูตร:
     `Rsys = P(sys works | m)Rm + P(sys works | m')(1 − Rm)`
- **สองวลีที่อาจารย์ย้ำให้จำ (สำคัญมาก):**
  - **"module works" = path shorted** (เปรียบเสมือนลัดวงจร — module หายไปจากไดอะแกรม)
  - **"module fails" = path opened** (เปรียบเสมือนทางขาด — module หายไปจากไดอะแกรม)
- `[ไม่แน่ใจ: อาจารย์พูดคำว่า "priority/property method" — น่าจะหมายถึงวิธีProbability แบบ conditional นี้เอง]`

### 5.2 การแกะจริงทีละขั้น (อาจารย์เริ่มจาก `E` แล้วสลับไป `B`)

- **กรณีเลือก m = E:**
  - อาจารย์ **พูดผิด/สลับก่อน แล้วแก้ตัวเอง** ("โทษที นี่กรณี fail ก่อน") — อยากให้เห็นว่าเขาตั้งใจแยกกรณีให้ถูก
  - **E fails → path E opened:** เหลือเส้นทางที่ผ่านได้คือ **(A และ B ต่อกัน) หรือ F** → คือ `(A·B)` ขนานกับ `F` แล้วค่อยต่อ **C, D อนุกรม**
    → `P(sys works|E') = [1 − (1 − RARB)(1 − RF)]·RC·RD` (ตรงสไลด์ 22)
  - **E works → path E shorted:** วงจร **ยัง non-series-parallel อยู่** (สไลด์ 23) → ต้องเลือก module ตัวต่อไป
- **ต่อด้วย m = B (ในกรณี E works):**
  - **B fails → path B opened:** ได้ `A` ขนานกับ **`(F·C)`** แล้วต่อ **`D` อนุกรม**
    → `[1 − (1 − RA)(1 − RFRC)]·RD` (สไลด์ 24)
  - **B works → path B shorted:** อาจารย์ชี้ว่า **ได้สมการเดียวกันกับกรณี B fails**
  - 🔑 **Insight ที่สไลด์ไม่ได้พูด:** เหตุผลคือ พอ **E ถูก short** แล้ว ไดอะแกรมที่ยุบได้จะ **ไม่มี B อยู่ในผังอีก** — ไม่ว่า B จะ short หรือ open ก็ยุบได้ topology เดียวกัน จึงได้ formula เดียวกัน (อาจารย์อธิบายว่า "มันเป็นกรณีเดียวกัน")
- **รวมทุกกรณี** (E' ; E&B' ; E&B) เข้า `Rsys = P(work|E)RE + P(work|E')(1−RE)` ตามสไลด์ 26

### 5.3 การเลือก Keystone — สิ่งที่อาจารย์ย้ำที่สุด

- **"การเลือก module แรกสำคัญมาก — ต้องเลือกให้ดี"** (สไลด์ 28: choosing the initial module is crucial)
- ถ้าเลือก **`A` เป็น keystone** จะ **ง่ายกว่ามาก**: ระบบจะกลายเป็น series-parallel ทันที
  (กรณี A works → ยุบเป็นผัง series-parallel; กรณี A fails → เหลือ `RF·RC·RD`)
- ถ้าเลือก module ที่ทำให้ยุบได้เร็ว/ไม่ต้องเลือกซ้ำหลายรอบ = ทำเร็วและไม่ยาก
- Heuristics (สไลด์ 28) ที่อาจารย์สื่อ: **เลือก module ที่อยู่บนหลาย path มากที่สุด** และ **คิดว่า module ไหนตัวเดียวที่ทำให้ระบบ "ไม่เป็น" series-parallel**
- อาจารย์ให้ทำโจทย์ในคาบ (สไลด์ 33/34) แล้ว **ให้เวลา ~5 นาที**

## 6. In-class Exercise: System P vs System Q (สไลด์ 33–34)

- **System P** = parallel ล้วน: สาขาบน `A→C`, สาขาล่าง `B→D` → `Rp = 1−(1−RaRc)(1−RbRd)`
- **System Q** = ระบบเดียวกันแต่มี **`K` เป็นสะพานเชื่อมกลาง** → เป็น non-series-parallel → **เลือก keystone = K**
- เหตุผลที่อาจารย์ไล่:
  - **K fails** → ทางของ K ขาด → เหลือแบบเดียวกับ **System P** พอดี
  - **K works** → ได้ configuration ที่ **ยืดหยุ่นกว่า** (มีทางเลือกเส้นทางมากกว่า)
- **ข้อสรุปที่อาจารย์ย้ำ:** **System Q มี reliability สูงกว่า System P** เพราะ Q = P เมื่อ K fail และดีกว่าเมื่อ K work → "ระบบที่มี bridge (non-SP) ให้ reliability ดีกว่าระบบ parallel ธรรมดา"
- ตรงกับพิสูจน์บนสไลด์: `Rq − Rp = 2R²(R−1)² ≥ 0` (เมื่อ `Rk = 1`)

## 7. TMR with Perfect Voter — และมุม "Mission Time" (สไลด์ 36)

- สูตรที่ใช้: `R = 3Rm² − 2Rm³`
- **คำถามที่อาจารย์ตั้ง:** "TMR ดีกว่า single จริงไหม?" → คำตอบคือ **ไม่เสมอ**
  - เขียนใหม่: `R = Rm[1 + (1−Rm)(2Rm−1)]`
  - **จุดตัด/เงื่อนไข: `Rm > 1/2`** — ถ้า `Rm < 1/2` **TMR แย่กว่า simplex** ควรใช้ single ธรรมดา
  - `[ไม่แน่ใจ: อาจารย์พูดตัวเลขช่วงนี้ว่า "1.2" กับ "0.15" — น่าจะเป็นการพูดเลขบนกราฟที่ฟังเพี้ยน ไม่ใช่ค่าจริง]`
- **มุมเวลาที่อาจารย์เน้นเพิ่ม (สำคัญ):**
  - มองกราฟ `R` เทียบเวลา: **Simplex = เส้นโค้งลงเรียบ ๆ**, **TMR = เส้นที่ตกชันกว่า** และ **ตัดกันที่ `λt = ln 2`**
  - **ถ้า Mission สั้น (อยู่ในช่วงก่อนตัดกัน) → เลือก TMR** จะได้ reliability สูงกว่า
  - **ถ้า Mission ยาว → simplex อาจดีกว่า** (TMR จะ MTTF ต่ำกว่า: `5/(6λ)` เทียบ `1/λ`)
  - อาจารย์สรุปว่า "ปกติเราดูที่ mission เป็นหลัก — ถ้าช่วง mission เหมาะกับ TMR ก็ใช้ TMR"

## 8. TMR with Imperfect Voter (สไลด์ 37)

- เมื่อ voter ไม่ perfect: `R = Rv(3Rm² − 2Rm³)`
- **เงื่อนไขบน voter:** `Rv > 1/(3Rm − 2Rm²)`
- **มุมที่อาจารย์เน้น:** เมื่อ `Rv` ไม่ใช่ 1 → **`Rm` ต้องตกอยู่ใน "ช่วง"** ไม่ใช่แค่ "มากกว่า"
  - ตัวอย่างในสไลด์: `Rv = 0.95` → ต้องมี **`0.56 < Rm < 0.94`**

  - ค่าต่ำสุดของ `Rv` ที่ยอมรับได้ (จุดก้น U) = **0.885**

## 9. TMR with Compensating Faults (สไลด์ 38) — กลไกที่อาจารย์แกะให้ดู

- ตั้ง `Rm = 1 − p0 − p1` (p0 = โอกาส fail ไปทาง 0, p1 = โอกาส fail ไปทาง 1)
- สูตร: `R = (3Rm² − 2Rm³) + 6p0p1Rm`
- **กลไกที่อาจารย์อธิบาย (ไม่ใช่แค่ท่องสูตร):**
  - ปกติ TMR เลือก **2 ใน 3** → ถ้ามี 2 ตัวผิด "ทางเดียวกัน" (เช่น ควรได้ 1 แต่สองตัวให้ 0) → **vote ออกมาผิด** (นี่คือกรณีทั่วไปของการเลือกผิด)
  - **แต่ถ้าตัวหนึ่ง fail ไปทาง 0 อีกตัว fail ไปทาง 1 (ทิศตรงข้ามกัน)** → error ทั้งสอง **หักกลบกัน** → เสียงข้างมากยังออกมาถูก → เกิด **Compensation**
  - ดังนั้นพจน์เพิ่มเติม `+6p0p1Rm` มาจากโอกาสที่ "fault สองตัวชดเชยกัน"
- **ตัวเลข RIF ที่อาจารย์อ้าง:** `RIF_TMR/Simplex = 125` และ `RIF_Compen/TMR = 1.6` (ดูสไลด์)

## 10. Voting: Bit-level vs Word-level และตัว Voter (สไลด์ 40–45)

- **Bit voter:** `y = x1x2 ∨ x2x3 ∨ x3x1` (คือ carry output ของ full-adder 1 บิต) — single error ถูก mask
- **ปัญหาเมื่อ N โตขึ้น:** gate-level design **บวมเร็วมาก** → จึงมีทางเลือกอื่น: **arithmetic** (บวก bits แล้วเทียบ threshold), **Mux-based**, **Selection-based** (majority = median)
- **จุดที่อาจารย์เน้น: ค่าที่ออกจากแต่ละ module อาจมี "หลายบิต" ไม่ใช่บิตเดียว** → ต้องคิดเรื่อง bit voting
- **คำเตือนสำคัญ (สไลด์ 42–44):** การ vote แบบ **bit-by-bit อาจอันตราย**
  - **Scenario 1** (ทุก module ผิดบิตเดียว): bit-voter ให้ `00000` (ตรงกับค่าที่ควรเป็น), word-voter ให้ 8
  - **Scenario 2** (บาง module ผิดหลายบิต): **bit-voter ให้ `17` ซึ่งไม่ตรงกับ input ตัวไหนเลย** ส่วน word-voter ให้ `00000` ที่ถูกต้อง
  - → **word voting ช่วยรักษา data integrity** ส่วน bit voting อาจได้ค่าที่ "ไม่มีอยู่ในความเป็นจริง"
- **ตัว voter ที่อาจารย์พูดถึง (สไลด์ 45):** ถ้า 3 ทางไม่ตรงกันหมด (disagreement) แล้ว "เลือกค่าไหนก็ได้" → ออกแบบง่าย ๆ ได้ด้วย **compare + XOR แล้วป้อนเข้า MUX** (มีสัญญาณ Disagree ไปเลือก) และขยายไป N ตัวได้

## 11. NMR / Standby / Hybrid / Self-purging (สไลด์ 46–50)

- **NMR:** ขยาย TMR เป็น N module (ปกติ N เป็นเลขคี่); 5MR ทำงานถูกตราบใดที่ยังมี 3 ใน 5 ดี; คู่ก็ทำได้ (4MR, 3-out-of-4) — แต่ **voter ยิ่งซับซ้อนขึ้นเร็วมากเมื่อ N เพิ่ม**
- **Standby redundancy:** ต้องมี **n-to-1 switch** เพื่อเลือก output ของ module ที่ active; ตัว detector ใช้ข้อมูลหลายทาง (error coding, reasonableness check, watchdog timer); พอ detect ได้ switch จะ flag ตัวเสียและเปิด spare ตัวถัดไป
  - **pair-and-spares** = ใช้ switch แบบ n-to-2 แล้ว **compare** output สองตัวที่เลือกมา
- **Hybrid redundancy:** มี n active + s spare → ต้องมี switch **(n+s)-to-n**; fault ถูก mask ที่ output แต่ก็ diagnose ได้ แล้วเอา spare เข้าแทน
- **Self-purging redundancy** (variant ของ hybrid): ตอนแรกให้ **ทุก module active**, แล้ว "purge" ตัวที่ disagree กับ majority ออก; voter เป็น **threshold voter** ที่ให้ weight `1` (active) / `0` (purged)
- **NMR/simplex variant ที่อาจารย์พูดถึง:** ใช้ voting unit ที่ "ตรวจ disagreement ได้ด้วย" → พอเจอตัวเสีย จะถอดตัวนั้น **และถอดอีกหนึ่งตัว** ออก → ทำให้ **vote ทุกครั้งไม่กำกวม** และ **ยืดอายุระบบ**
- อาจารย์สรุปเชิง design ว่า **static redundancy ทำให้การทดสอบ fault ยุ่งยากขึ้น** — ต้องมั่นใจว่าตอนเริ่มต้น **redundant components ทุกตัว fault-free หมด** [ตรงสไลด์ 50]

## 12. Time Redundancy / Recompute / EDDI / Mixed Space-Time (สไลด์ 51, 54–59)

- **ไอเดีย:** **คำนวณซ้ำ** แล้วเช็คว่าผลตรงกันไหม — ใช้ได้ดีกับ **transient fault**; **ไม่ช่วยกับ permanent fault** (จะได้ผลผิดเหมือนเดิม) เว้นแต่ "เปลี่ยน operand ให้ต่างเดิม" เช่น คำนวณ `2(a·b)` แทน `(2a)·b` หรือ `b+a` แทน `a+b`
- **ปัญหาเวลาที่อาจารย์ย้ำ:** replication in time **ช้า** (มี penalty ด้านเวลา) แต่ในหลายงาน control **มีเวลาเหลือพอ** → จึงยอมได้
- **Mixed space/time:** แทนที่จะซ้ำด้วย hardware เดิม (ช้า, T=5) หรือทำ hardware ซ้ำทั้งหมด (แพง) → **เพิ่ม hardware บางส่วน** เพื่อให้ recompute ทำ interleave ได้เร็วขึ้น (ได้ T=3)
- **EDDI (Error Detection by Duplicated Instructions):** เขียนโค้ดซ้ำ (เช่น `add` เฉพาะ register คนละชุด แล้ว `bne` เทียบ) และ **compare ก่อนทำ store**
- **แนวคิด "mix" ที่อาจารย์พูด:** ทำซ้ำทั้ง computation, store เป็น duplicate, สื่อสารแบบ duplicate; ปกติใช้ TMR กับ computation/communication `[ไม่แน่ใจ: ท่อนนี้สำเนียงเพี้ยน และพูดว่า "เป็นตัวอย่างโค้ด มันไม่จบ" — เหมือนยังอธิบายไม่ครบ]`

## 13. Alternating Logic (สไลด์ 61–64)

- **ไอเดียหลัก:** แทนที่จะใช้ logic ธรรมดา → **แปลงค่า/เขียนฟังก์ชันในรูปอื่น** แล้วส่งข้อมูล 2 รอบ (ข้อมูล + complement) แล้ว **เปรียบเทียบ (XNOR/XOR)**
- **dual ของฟังก์ชัน** `fd`: ได้จากการ **สลับ AND ↔ OR** ในนิพจน์ (เช่น `f = ab ∨ c` → `fd = (a∨b)c`)
- **ข้อได้เปรียบเทียบกับ duplication:** ลดโอกาส **common error** (เพราะใช้เส้นทาง/รูปแบบการทำงานต่างกัน)
- **self-dual function:** ถ้า `f = fd` → ใช้ **วงจรเดียวกันคำนวณ 2 ครั้ง** (time redundancy) ได้; full-adder (sum และ carry) เป็น self-dual
- **Recompute after shift / swap:** สำหรับการบวก ใช้ shift หรือ swap operands เป็น encode/decode (เช่น `b+a` แทน `a+b`) ทำให้วงจร adder ถูก "ออกกำลัง" ต่างกันแต่ละรอบ
- `[ไม่แน่ใจ: ท่อน 01:06–01:07 อาจารย์พูดถึง encode/decode แล้ว XOR/XNOR เทียบกับค่าเดิม — คำว่า "เจมส์/XNOR" ฟังไม่ชัด]`

## 14. Fail-Safe Systems (สไลด์ 66–69)

- **นิยามเชิง intuition ที่อาจารย์ยก:** พยายามให้เวลา "fail" แล้วมันไปอยู่ใน **สถานะที่ปลอดภัย** เสมอ
- **ตัวอย่างที่ใช้:** **ไฟจราจร fail-safe → ไฟแดงทั้งหมด** (ห้ามเขียวทั้งหมด); อีกตัวอย่างคือ **วาล์วแก๊ส/เตาหุงต้ม** ที่พอเปลวไฟดับจะปิดแก๊ส
  - `[ไม่แน่ใจ: มีท่อนหนึ่งอาจารย์พูดว่า "ของเราจะกระพริบ" — ไม่ชัดว่าหมายถึงระบบใด]`
- หลักการ: ต้องมี **อย่างน้อย 2 output line** ที่บอกรวมกันได้ทั้ง "output ปกติ" และ "safe failure condition" (เช่น two-rail encoding `0:01, 1:10, F:00, 11`) — เพราะถ้ามีบรรทัดเดียว ค่าที่ค้างอยู่ผิดฝั่งจะไม่ปลอดภัย
- รูปแบบที่อาจารย์ไล่ในสไลด์: **Fail-safe 2-out-of-4 code checker** (output `fg` จะกลายเป็น `00` อย่างถาวรเมื่อเจอ unsafe condition ครั้งแรก) และ **Fail-safe State Machine** (encode state ด้วย Berger code, เขียน next-state ให้ถูกบังคับไป error state เมื่อผิด)
- `[ไม่แน่ใจ: ตัวอย่าง "รถไฟสวนสนุก" ของสไลด์ 67 (sB/sE) อาจารย์พูดถึงหรือไม่ ไม่ปรากฏชัดในทรานสคริปต์]`
