# Part 7 — Fault Masking

## แนวคิดตั้งต้น: ทำให้ความผิดพลาดหายไปก่อนที่มันจะกลายเป็นปัญหา

ในบทก่อน ๆ เราเรียนวิธีตรวจจับความผิดพลาดด้วยรหัสและวงจร self-checking แต่การตรวจจับเป็นเพียงครึ่งเดียวของเรื่อง เพราะเมื่อเราตรวจจับได้แล้ว เรายังต้องตัดสินใจว่าจะทำอะไรต่อ บทนี้เสนอทางเลือกอีกทางหนึ่งที่ฉลาดมาก นั่นคือแทนที่จะตรวจจับแล้วค่อยแก้ไข เราจะออกแบบระบบให้ **บังความผิดพลาดไปเลย** โดยไม่ต้องรู้ด้วยซ้ำว่ามีความผิดพลาดเกิดขึ้น นี่คือแนวคิดของ fault masking

เริ่มจากแผนภาพที่บอกว่าเราจัดการกับ fault ได้สองแนวทางครับ แนวทางแรกคือ **Avoid** ซึ่งหมายถึงการหลีกเลี่ยงไม่ให้ความผิดพลาดเกิดขึ้นหรือเข้ามาในระบบ แบ่งได้เป็นการป้องกันด้วย quality assurance และการทดสอบในขั้นตอนออกแบบ แนวทางที่สองคือ **Tolerate** ซึ่งหมายถึงการยอมรับว่าความผิดพลาดจะต้องมี แล้วออกแบบให้ระบบทนมันให้ได้ แนวทางนี้ยังแยกต่อไปเป็น **Dynamic redundancy** ที่ตรวจความผิดพลาดแล้วสลับเอาชิ้นส่วนสำรองเข้ามา กับ **Static redundancy** ที่บังความผิดพลาดไว้ที่ผลลัพธ์เลย แผนภาพยังไล่สถานะของชิ้นส่วนหรือระบบไว้หลายระยะ ตั้งแต่ perfect, fixed, injured, screened, faulty, faulty-safe, degraded, restored จนถึง unaffected

มีแผนภาพอีกอันที่สำคัญมากเพราะมันคือรูปที่แนบมากับข้อสอบเก่าครับ นั่นคือแผนภาพ **Design Techniques** ซึ่งแสดงให้เห็นสายพานจากสาเหตุไปสู่ผลลัพธ์ โดยมี specification mistake, implementation mistake, external disturbance และ component defect ไหลเข้าไปเป็น software fault และ hardware fault จากนั้นเข้าเป็น **Errors** แล้วเข้าเป็น **System failures** โดยมีวงเล็บสามอันคั่นอยู่ วงเล็บแรกคือ **Fault Avoidance** ซึ่งอยู่ก่อนถึง fault วงเล็บที่สองคือ **Fault Masking** ซึ่งอยู่ระหว่าง fault กับ error และวงเล็บที่สามคือ **Fault Tolerance** ซึ่งอยู่ระหว่าง error กับ failure แผนที่นี้ควรจำไว้ให้ขึ้นใจ

## สามตัวเลือกของ fault tolerance

สไลด์ให้ตัวเลือกสำหรับการทนทานต่อความผิดพลาดไว้สามข้อครับ ข้อแรกคือ **Detect and replace** ซึ่งเป็น dynamic redundancy แบบ cold หรือ hot standby โดยมีตัวตรวจที่ใช้ coding, watchdog timer, self-checking หรือ duplication แบบ pair-and-spares และมีชิ้นส่วนสำรอง เมื่อตรวจพบความผิดพลาดก็สลับชิ้นส่วนสำรองเข้ามา ข้อที่สองคือ **Mask** ซึ่งเป็น static redundancy โดยใช้ voter เลือกเสียงข้างมากจากหลายชิ้นส่วน ความท้าทายของวิธีนี้คือต้อง synchronise ให้ทันกันเพื่อโหวต และต้องจัดการกับกรณีที่ผลลัพธ์แต่ละชิ้นไม่ตรงกันแบบคลุมเครือ และข้อที่สามคือ **Mask, diagnose และ reconfigure** ซึ่งเป็น hybrid redundancy ที่บังความผิดพลาดที่ผลลัพธ์ แต่ก็ยังวินิจฉัยได้ เช่นด้วยการเปรียบเทียบกับผลลัพธ์ของ voter แล้วเอาชิ้นส่วนที่เสียออกไปแทนที่ด้วยชิ้นส่วนสำรอง และเมื่อชิ้นส่วนสำรองหมด มันก็จะกลายเป็น static

สไลด์เปรียบเทียบข้อดีข้อเสียของทั้งสามครับ แบบ cold standby นั้นใช้พลังงานน้อยและมีอายุยืน เพราะเราแค่เพิ่มชิ้นส่วนสำรอง แต่ coverage และความหน่วงในการทนทานเป็นข้อเสีย แบบ voting ให้การบังความผิดพลาดทันทีและให้ safety สูง แต่ต้องแลกด้วยพลังงานและพื้นที่ และ voter เองกลายเป็นจุดวิกฤต ส่วนแบบ hybrid ให้ทั้งการบังทันที อายุยืน และ safety สูง แต่ก็ยังมี penalty และ switch-voter กลายเป็นจุดวิกฤต

## การบังความผิดพลาดโดยธรรมชาติของวงจรลอจิก

ความจริงที่น่าสนใจคือ วงจรลอจิกเองก็มีความสามารถในการบังความผิดพลาดอยู่แล้วตามธรรมชาติครับ ลองพิจารณา AND gate กับ OR gate ใน AND gate นั้น ถ้า input บางตัวเกิด fault แบบหนึ่งไปศูนย์ ซึ่งก็คือ 1 กลายเป็น 0 ผลลัพธ์จะเปลี่ยนไปจริง เราจึงเรียก fault นี้ว่า **critical** แต่ถ้า input เกิด fault แบบศูนย์ไปหนึ่ง ผลลัพธ์จะไม่เปลี่ยนเลย เพราะ AND ต้องการหนึ่งครบทุกตัวอยู่แล้ว จึงถูก **mask** ไว้ ใน OR gate นั้นกลับกัน คือ fault หนึ่งไปศูนย์เป็นแบบ critical แต่ fault ศูนย์ไปหนึ่งกลับถูก mask

จากข้อสังเกตนี้ สไลด์จึงตั้งคำถามว่า เราจะใช้ประโยชน์จากความสามารถในการบังความผิดพลาดที่มีอยู่แล้วตามธรรมชาติของ gate นี้เพื่อให้ได้ fault tolerance ได้หรือไม่ คำตอบคือ **Interwoven redundant logic** หรือการสานความซ้ำซ้อนเข้าด้วยกัน ลองให้ x1, x2, x3 และ x4 เป็นสำเนาสี่ชุดของสัญญาณ x เมื่อเราสลับชั้นของ AND และ OR ไปมา ชั้นหนึ่งจะบัง critical fault ของอีกชั้นหนึ่งไว้ได้ สไลด์บอกว่าเพื่อบัง h ความผิดพลาด จำนวน gate และ input จะต้องถูกขยายตามตัวคูณที่ขึ้นกับ h บวกหนึ่ง และสำหรับกรณี h เท่ากับหนึ่ง เราเรียกแบบแผนนี้ว่า **Quadded logic** สไลด์ยังแสดงตัวอย่างของ half-adder ที่สร้างด้วย quadded logic ไว้ด้วย

## การคำนวณความน่าเชื่อถือแบบ combinatorial modelling

ส่วนนี้คือการนำคณิตศาสตร์เรื่องความน่าเชื่อถือจากบทที่สองกลับมาใช้ในบริบทของ fault masking ครับ สมมติฐานพื้นฐานคือ ชิ้นส่วนต่าง ๆ พังอย่างเป็นอิสระต่อกัน เมื่อชิ้นส่วนใดพังแล้วให้ถือว่ามันให้ผลลัพธ์ผิดเสมอ และระบบจะถือว่าพังถ้าไม่เป็นไปตามเซตขั้นต่ำของชิ้นส่วนที่จำเป็นต้องทำงาน

สำหรับระบบแบบ **series** ค่าความน่าเชื่อถือคือผลคูณของค่าความน่าเชื่อถือของทุกชิ้นส่วน สำหรับระบบแบบ **parallel** ค่าความน่าเชื่อถือคือหนึ่งลบผลคูณของ (หนึ่งลบ R) ของทุกชิ้นส่วน และสำหรับระบบที่ **ไม่ใช่ series-parallel** เราใช้วิธี conditioning บน keystone module เหมือนที่เราเรียนในบทที่สอง คือค่าความน่าเชื่อถือของระบบเท่ากับความน่าจะเป็นที่ระบบทำงานเมื่อ keystone ทำงาน คูณค่า R ของ keystone บวกความน่าจะเป็นที่ระบบทำงานเมื่อ keystone พัง คูณ (หนึ่งลบ R ของ keystone)

สไลด์ของบทนี้ยกตัวอย่างเครือข่าย bridge หก module ที่มี E เป็นตัวพาดกลาง แล้วทำการ condition บน E ก่อน จากนั้น condition บน B อีกครั้งในกิ่งหนึ่ง จนได้ผลลัพธ์ว่าเมื่อทุก module มีค่า R เท่ากัน พหุนามของระบบคือ R ยกกำลังหก ลบ สาม R ยกกำลังห้า บวก R ยกกำลังสี่ บวก สอง R ยกกำลังสาม และสไลด์ยังแนะนำว่า keystone ที่เลือกควรเป็น A มากกว่า E เพราะเมื่อ condition บน A เครือข่ายจะแยกออกเป็นสองชิ้น series-parallel ทันที ซึ่งเป็นการประยุกต์ heuristic ที่ว่าให้เลือกชิ้นส่วนที่อยู่บนเส้นทางมากที่สุด หรือชิ้นส่วนที่เมื่อ fix แล้วทำให้เครือข่ายกลายเป็น serial หรือ parallel

## TMR, NMR และรายละเอียดที่ลึกขึ้น

เราได้พูดถึง TMR ในบทที่สองไปแล้ว แต่ในบทนี้สไลด์ลงรายละเอียดที่ลึกกว่าครับ ขอทวนสั้น ๆ ก่อนว่า TMR มีค่า reliability เท่ากับสาม R sub m กำลังสอง ลบ สอง R sub m กำลังสาม คูณ R sub V โดยที่ TMR จะดีกว่า simplex ก็ต่อเมื่อ R sub m มากกว่าหนึ่งส่วนสอง และค่า MTTF ของ TMR นั้นเท่ากับห้าส่วนหก lambda ซึ่งต่ำกว่า simplex ที่เป็นหนึ่งส่วน lambda

สำหรับกรณี voter ไม่สมบูรณ์แบบ เงื่อนไขบน voter คือ R sub V ต้องมากกว่าหนึ่งหารด้วย (สาม R sub m ลบ สอง R sub m กำลังสอง) และเงื่อนไขบน module คือ R sub m ต้องอยู่ระหว่าง (สามลบรากที่สองของ (เก้าลบแปดหาร R sub V)) หารสี่ กับ (สามบวกรากที่สองของ (เก้าลบแปดหาร R sub V)) หารสี่ ตัวอย่างเช่นถ้า R sub V เท่ากับ 0.95 แล้ว R sub m ต้องอยู่ระหว่าง 0.56 กับ 0.94

กรณี compensating fault นั้นพิจารณาว่า module อาจพังได้สองทิศทาง ถ้า R sub m เท่ากับหนึ่งลบ p0 ลบ p1 แล้วค่า reliability เท่ากับ (สาม R sub m กำลังสอง ลบ สอง R sub m กำลังสาม) บวก หก p0 p1 R sub m โดยเทอมหลังเกิดจากกรณีที่ module หนึ่งพังไปทาง 0 และอีก module หนึ่งพังไปทาง 1 ซึ่ง module ที่สามยังถือเสียงข้างมากได้ ตัวอย่างเช่นถ้า R sub m เท่ากับ 0.998 และ p0 กับ p1 เท่ากับ 0.001 ค่า reliability จะเป็น 0.999990 ซึ่งปรับปรุงเหนือ TMR พื้นฐานประมาณ 1.6 เท่า

การขยาย TMR ไปสู่ **N-Modular Redundancy** หรือ NMR ทำได้โดยใช้ N module พร้อม voter โดย N มักเป็นเลขคี่ ตัวอย่างเช่น 5MR จะทำงานถูกต้องตราบใดที่มีอย่างน้อยสามในห้า module ที่ยังดี และความซับซ้อนของ voter จะโตขึ้นอย่างรวดเร็วเมื่อ N เพิ่มขึ้น ส่วน N ที่เป็นเลขคู่ก็ทำได้ เช่น 4MR ที่โหวตแบบ 3-out-of-4 ซึ่งบัง single fault ได้และยังออกแบบให้ตรวจจับ double fault ได้ด้วย

## ตัวโหวต และความต่างระหว่างการโหวตระดับบิตกับระดับคำ

มาดูรายละเอียดของ voter ครับ bit-voter ของ TMR ที่ง่ายที่สุดคือ y เท่ากับ x1x2 บวก x2x3 บวก x3x1 ซึ่งจริง ๆ แล้วคือ carry output ของ single-bit full-adder นั่นเอง แต่ถ้าเป็น 5MR หรือ 7MR การออกแบบระดับ gate จะระเบิดขนาดขึ้นอย่างรวดเร็ว จึงมีวิธีอื่น เช่นแบบที่ใช้การบวกบิตแล้วเทียบกับ threshold, แบบที่ใช้ mux และแบบที่อิงการเลือกค่า median

มีประเด็นสำคัญที่ต้องระวังมากครับ นั่นคือการโหวตระดับคำหรือ word voting นั้นต่างจากการโหวตระดับบิตหรือ bit voting และการโหวตทีละบิตอาจให้ผลลัพธ์ที่อันตรายกว่า ลองดูตัวอย่างนี้ สมมติ module สามตัวให้ค่า 00, 10 และ 11 ถ้าเราโหวตทีละบิต ผลลัพธ์จะเป็น 10 ซึ่งไม่ตรงกับ input ตัวใดเลย แม้ว่าแต่ละบิตจะมาจากเสียงข้างมากก็ตาม สไลด์จึงอภิปรายการออกแบบทั้ง bit-voting และ word-voting network ไว้ และแสดง scenario ที่ทุก module มี error บิตที่ output และ scenario ที่บาง module มี error หลายบิต เพื่อเน้นเรื่องการรักษาความสมบูรณ์ของข้อมูล

## Standby และ hybrid redundancy

ใน **standby redundancy** เรามี switch แบบ n-to-1 เพื่อเลือกผลลัพธ์ของ module ที่กำลังทำงานอยู่ และมี detector ที่ใช้ข้อมูลต่าง ๆ เช่น error coding, reasonableness check และ watchdog timer ในการตัดสินว่ามี fault เกิดขึ้น เมื่อตรวจพบ switch ก็จะจัดระบบใหม่โดยทำเครื่องหมายชิ้นส่วนที่เสียและเปิดใช้ชิ้นส่วนสำรองตัวถัดไปตามลำดับ ถ้าเราใช้ switch แบบ n-to-2 แล้วเปรียบเทียบผลลัพธ์สองตัวที่เลือกได้ การจัดแบบนี้เรียกว่า **pair-and-spares**

ใน **hybrid redundancy** ที่มี module ทำงาน n ตัวและมีชิ้นส่วนสำรอง s ตัว เราต้องใช้ switch แบบ (n บวก s)-to-n เพื่อเลือกผลลัพธ์ของ module ที่ทำงานอยู่ สำหรับ **Self-purging redundancy** ซึ่งเป็นรูปแบบหนึ่งของ hybrid นั้น module ทุกตัวจะทำงานตั้งแต่เริ่ม แต่จะถูก purge ทิ้งเมื่อผลลัพธ์ไม่ตรงกับเสียงข้างมาก และ voter ในระบบนี้จะเป็น threshold voter ที่ให้ค่าน้ำหนักหนึ่งกับ module ที่ยังทำงานและให้ศูนย์กับ module ที่ถูก purge แล้ว

ยังมีความหลากหลายอื่น ๆ เช่น NMR/simplex ที่แทนที่ voting unit ด้วยตัวที่สามารถตรวจความไม่ตรงกันได้ด้วย เมื่อพบชิ้นส่วนที่เสีย ชิ้นส่วนนั้นพร้อมกับอีกชิ้นส่วนหนึ่งจะถูกถอดออกจากระบบ ซึ่งทำให้การโหวตชัดเจนขึ้นและยืดอายุของระบบ และสไลด์ยังเตือนว่า static redundancy ทำให้การทดสอบ fault ยากขึ้น เพราะเพื่อให้ static redundancy ได้ผล เราต้องมั่นใจว่าชิ้นส่วนที่ซ้ำซ้อนทุกตัวปลอดจาก fault ตั้งแต่เริ่มต้น และมันเป็นแบบ controllable แต่ไม่ observable

## Time redundancy และการประยุกต์ในระบบจริง

**Time redundancy** หรือการใช้เวลาซ้ำซ้อนมีแนวคิดง่าย ๆ ครับ นั่นคือการทำซ้ำหรือ retry ซึ่งเหมาะกับความผิดพลาดแบบชั่วคราวเป็นพิเศษ แต่ข้อจำกัดคือการทำ computation ซ้ำนั้นไม่มีประโยชน์กับความผิดพลาดแบบถาวร เพราะชิ้นส่วนที่เสียจะให้ผลผิดเหมือนเดิมทุกครั้ง เราอาจเลี่ยงปัญหานี้ได้โดยการเปลี่ยน operand เล็กน้อย เช่นคำนวณ a คูณ (2b) แทนที่จะเป็น (2a) คูณ b หรือคำนวณ b บวก a หรือลบ(-a ลบ b) แทนที่จะเป็น a บวก b

สำหรับการประยุกต์หรือ systems จริง **Space Shuttle** ใช้ 5-way redundancy ในฮาร์ดแวร์ เดิมมีสามชิ้นทำงานบวกสำรองสองชิ้นคือ warm หนึ่ง cold หนึ่ง ต่อมาเปลี่ยนเป็นสี่ชิ้นทำงานบวกสำรองหนึ่งชิ้น และยังใช้ซอฟต์แวร์ที่พัฒนาอย่างอิสระสองระบบ ซึ่งก็คือ design diversity นั่นเอง ส่วนรถไฟหัวกระสุน **Shinkansen** ของญี่ปุ่นใช้ระบบ triple-duplex ซึ่งเป็น redundancy หกเท่า

สไลด์สรุป hardware redundancy ทั้งหมดออกเป็นสามกลุ่มครับ กลุ่ม **data path** ประกอบด้วย replication in space เช่น duplication และ comparison, triplication และ vote, pair-and-spare และ NMR หรือ hybrid รวมถึง replication in time เช่น recompute และ compare หรือ vote, alternating logic, การคำนวณซ้ำหลังการ shift, การคำนวณซ้ำหลังการ swap และการทำสำเนา operand segment รวมถึง mixed space-time replication และ low-redundancy coding เช่น parity prediction, residue checking และ self-checking design กลุ่ม **control unit** ประกอบด้วย coding of control signal, control-flow watchdog และ self-checking design และกลุ่ม **glue logic** ประกอบด้วย self-checking design และ monitoring เช่น watchdog timer และ activity monitor

## Alternating logic

**Alternating logic** เป็นเทคนิคที่ฉลาดมากสำหรับการส่งข้อมูลบนเส้นหรือบัสที่ไม่น่าเชื่อถือครับ แนวคิดคือ ส่งข้อมูลชุดหนึ่งแล้วเก็บไว้ที่ปลายทาง จากนั้นส่ง bitwise complement ของข้อมูลนั้น แล้วเปรียบเทียบสองเวอร์ชันที่ได้ วิธีนี้ตรวจจับเส้นที่ stuck-at-0 หรือ stuck-at-1 ได้ รวมถึงตรวจจับความผิดพลาดแบบชั่วคราวได้หลายแบบด้วย ข้อดีเมื่อเทียบกับ duplication คือความน่าจะเป็นที่จะเกิด common error นั้นต่ำกว่า

เพื่อให้เข้าใจ alternating logic ต้องรู้จัก dual ของฟังก์ชันบูลีนก่อนครับ dual ของฟังก์ชัน f คือฟังก์ชัน fd ที่มีสมบัติว่า เมื่อ input ถูกคอมพลีเมนต์ ค่าของ fd จะเท่ากับ complement ของค่าของ f เราหา dual ได้โดยการสลับ AND กับ OR ใน expression เช่น dual ของ f เท่ากับ ab หรือ c คือ fd เท่ากับ (a หรือ b) คูณ c และถ้าฟังก์ชันใดมีสมบัติว่า f เท่ากับ fd เราเรียกฟังก์ชันนั้นว่า **self-dual** ซึ่งหมายความว่าเราสามารถคำนวณ f และ fd ด้วยวงจรเดียวกันได้ ทำให้ประหยัดฮาร์ดแวร์ด้วยวิธีเวลา redundancy ตัวอย่างที่น่าสนใจคือ ทั้ง sum ซึ่งเท่ากับ a XOR b XOR c และ carry ซึ่งเท่ากับ ab หรือ bc หรือ ca ของ full-adder ต่างเป็น self-dual และแม้แต่ k-bit binary adder ที่มี 2k บวกหนึ่ง input และ k บวกหนึ่ง output ก็เป็น self-dual รวมถึงเวอร์ชัน 1's-complement และ 2's-complement ด้วย

ยังมีเทคนิค **recomputing with transformed operands** ซึ่งเป็น generalization ของ alternating logic โดยใช้ encode และ decode เป็นการคอมพลีเมนต์ทีละบิต เมื่อฟังก์ชัน f คือการบวกฐานสอง เราอาจใช้การ shift เป็น encode และ decode ได้ ซึ่งทำให้วงจร adder ถูกใช้งานในลักษณะที่ต่างกันในแต่ละครั้ง หรืออาจใช้การ swap เช่นสลับ operand สองตัวคือคำนวณ b บวก a แทน a บวก b หรือสลับครึ่งบนกับครึ่งล่างของ operand และยังมีการบวกแบบ **segmented addition** ที่แบ่ง operand และ adder ออกเป็นสองหรือสามส่วน แล้วทำ replicated addition บนส่วนเหล่านั้นพร้อมใช้ comparison หรือ voting ในการตรวจจับหรือแก้ไข

## Fail-safe systems

**Fail-safe** คือคุณสมบัติของระบบที่เมื่อมันล้มเหลวเพราะเหตุการณ์ที่ไม่พึงประสงค์ซึ่งมันทนไม่ได้ มันจะผลิตผลลัพธ์ออกมาอยู่ในชุดที่ปลอดภัยที่กำหนดไว้ล่วงหน้าเสมอ ตัวอย่างที่เห็นภาพคือไฟจราจรแบบ fail-safe ที่เมื่อเสียจะค้างอยู่ที่สีแดง หรือ pilot ของเตาแก๊สที่เมื่อเปลวไฟดับลงจะปิดวาล์วแก๊สทันที

มีจุดสำคัญที่ต้องจำครับ ระบบดิจิทัลแบบ fail-safe จำเป็นต้องมี output แบบ binary อย่างน้อยสองเส้น โดยที่ทั้งสองเส้นรวมกันแทนทั้งผลลัพธ์ปกติและสภาพความล้มเหลวที่ปลอดภัย เหตุผลคือ ถ้าเรามี output เพียงเส้นเดียว แม้ว่าค่าหนึ่งเช่น 0 จะปลอดภัยโดยธรรมชาติ แต่ถ้า output ค้างอยู่ที่ค่าอีกค่าหนึ่งก็จะไม่ปลอดภัย การใช้ two-rail encoding เป็นทางเลือกหนึ่ง โดยแทนค่า 0 ด้วย 01 ค่า 1 ด้วย 10 และแทนค่า failure ด้วย 00 หรือ 11 หรือทั้งคู่

เรายังแบ่งระดับความ fail-safe ครับ **Totally fail-safe** หมายถึงการผลิต erroneous output ที่ปลอดภัยเท่านั้น ตราบที่ไม่มี failure อีกอันเกิดขึ้นก่อนที่อันปัจจุบันจะถูกตรวจพบ ส่วน **Ultimate fail-safe** หมายถึงการผลิต erroneous output ที่ปลอดภัยเท่านั้นตลอดไป

สไลด์ยกตัวอย่างระบบความปลอดภัยของรถไฟในสวนสนุกให้เป็นโจทย์ด้วยครับ โดยมีสัญญาณ sB บอกว่ารถอยู่ต้นราง ซึ่งเดินหน้าได้แต่ไม่ควรถอย และสัญญาณ sE บอกว่าอยู่ปลายราง ซึ่งถอยได้แต่ไม่ควรเดินหน้า แล้วถามว่าข้อกำหนดนี้สอดคล้องและครบถ้วนหรือไม่ คำตอบคือไม่ครบถ้วน เพราะมันไม่ได้บอกว่าจะเกิดอะไรขึ้นถ้า sB เท่ากับ sE เท่ากับหนึ่ง ซึ่งตามปกติไม่ควรเกิดขึ้น แต่เพราะเซ็นเซอร์มักถูกออกแบบให้ fail แบบปลอดภัย การผสมนี้จึงไม่ใช่เรื่องที่เป็นไปไม่ได้ และความครบถ้วนจะช่วยป้องกันปัญหาในการนำไปใช้หรือปัญหาด้านความปลอดภัย

มีตัวอย่าง **Fail-safe 2-out-of-4 code checker** ที่น่าสนใจครับ input สี่บิต abcd ต้องมีหนึ่งพอดีสองตัว ผลลัพธ์ fg จะเป็น 01 หรือ 10 ถ้า input ถูกต้อง เป็น 00 ซึ่งเป็น safe erroneous output และเป็น 11 ซึ่งเป็น unsafe erroneous output และ output จะกลายเป็น 00 อย่างถาวรเมื่อเกิด unsafe condition ครั้งแรก โดยอาศัย flip-flop ที่มี preset set และ reset

สุดท้ายคือ **Fail-safe state machine** ซึ่งใช้ error code ในการเข้ารหัส state และออกแบบ next-state logic ให้เครื่องถูกบังคับไปยัง error state เมื่อมีอะไรผิดพลาด วิธีออกแบบวิธีหนึ่งคือใช้ Berger code สำหรับ state โดยหลีกเลี่ยง state ที่เป็นศูนย์ทั้งหมดเมื่อบิตตรวจสอบเป็นหนึ่งทั้งหมด และในทางกลับกัน จากนั้น implement next-state equation ในรูป sum-of-products สำหรับบิต state หลัก และในรูป product-of-sums สำหรับบิตตรวจสอบ state machine ที่ได้จะ fail-safe ภายใต้ unidirectional error และค่า hardware overhead สำหรับเครื่องที่มี n state จะเป็นบิต state เพิ่มขึ้นในอันดับของ log log n บวกกับ next-state logic และ Berger code checker ที่ต่อกับ state flip-flop

## สรุปสิ่งที่ต้องจำ และกับดักที่ต้องระวัง

ทบทวนครับ จำแผนที่ของ Fault Avoidance, Fault Masking และ Fault Tolerance บนสายพาน จำการบังความผิดพลาดโดยธรรมชาติใน AND และ OR รวมถึง quadded logic ที่ h เท่ากับหนึ่ง จำสูตร series และ parallel จำวิธี keystone conditioning และพหุนามของ bridge จําเงื่อนไขที่ TMR ดีกว่า simplex เมื่อ R มากกว่าครึ่ง จำ NMR, standby, hybrid และ self-purging จำ alternating logic และแนวคิด self-dual และจำว่า fail-safe ต้องมี output อย่างน้อยสองเส้น

กับดัก ข้อแรก ระบบ fail-safe ต้องมี output อย่างน้อยสองเส้น อย่าออกแบบให้มีเส้นเดียว ข้อที่สอง static redundancy ทำให้การทดสอบ fault ยากขึ้น และเราต้องมั่นใจว่าชิ้นส่วนปลอด fault ตั้งแต่เริ่ม ข้อที่สาม bit voting ต่างจาก word voting และการโหวตทีละบิตอาจให้ผลลัพธ์ที่ไม่ตรงกับ input ใด ๆ เลย และข้อที่สี่ TMR ที่ module มีความน่าเชื่อถือสูงมากอาจแย่กว่า simplex เพราะ voter กลายเป็นจุดพังใหม่ที่เพิ่มเข้ามา


## จากคำบรรยายในห้อง [insights]

**สองวลีที่อาจารย์ย้ำให้จำสำหรับ keystone** คือเวลาบังคับให้ module ทำงาน ให้คิดว่า **"module works = path shorted"** คือลัดวงจร เส้นทางของ module นั้นหายไป และเวลาบังคับให้ module พัง ให้คิดว่า **"module fails = path opened"** คือทางขาด นี่เป็นวิธีคิดที่ทำให้การยุบวงจรง่ายกว่าการจำสูตร

**Insight ที่สไลด์ไม่ได้พูดชัด** อาจารย์ชี้ว่าในตัวอย่างบริดจ์หกโมดูล พอเราบังคับ E ให้ลัดวงจร (E works) แล้ว ไดอะแกรมที่ยุบได้จะ**ไม่มี B อยู่ในผังอีกต่อไป** ดังนั้นไม่ว่า B จะทำงานหรือพัง ก็จะยุบได้ topology เดียวกันและได้สูตรเดียวกัน นี่คือเหตุผลว่าทำไมสองกรณี B works กับ B fails จึงให้ผลลัพธ์เท่ากัน และยังย้ำว่า **การเลือก module แรกสำคัญมาก** ถ้าเลือก A เป็น keystone จะง่ายที่สุดเพราะระบบกลายเป็น series-parallel ทันที

**โจทย์ System P กับ System Q** อาจารย์ให้ทำในคาบ โดย P เป็นระบบขนานล้วนที่มีสองสาขา A ต่อ C และ B ต่อ D ส่วน Q เป็นระบบเดียวกันที่มี K เป็นสะพานเชื่อมกลาง ซึ่งทำให้เป็น non-series-parallel และเลือก K เป็น keystone คำตอบสรุปคือ **Q มี reliability สูงกว่า P** เพราะเมื่อ K พัง Q จะกลายเป็น P พอดี และเมื่อ K ทำงาน Q จะมีทางเลือกเส้นทางมากกว่า ตรงกับผลต่าง Rq ลบ Rp เท่ากับ สอง R กำลังสอง คูณ (R ลบหนึ่ง) กำลังสอง ซึ่งมากกว่าหรือเท่ากับศูนย์

**TMR กับเส้นโค้งในแกนเวลา** อาจารย์เน้นว่าถ้าดู R เทียบเวลา เส้นของ simplex จะลาดลงเรียบ ๆ แต่เส้นของ TMR จะตกชันกว่า และ **ตัดกันที่ lambda t เท่ากับ ln 2** ดังนั้นถ้า **mission สั้น** ซึ่งอยู่ในช่วงก่อนจุดตัด ให้เลือก TMR แต่ถ้า **mission ยาว** simplex อาจดีกว่า เพราะ MTTF ของ TMR ต่ำกว่า สำหรับกรณี voter ไม่สมบูรณ์แบบ กราฟเป็นรูปตัว U และค่าต่ำสุดของ voter reliability ที่ยอมรับได้คือประมาณ 0.885

**คำเตือนเรื่อง bit voting** อาจารย์ยกตัวอย่างที่สำคัญว่า การโหวตทีละบิตอาจให้ผลลัพธ์ที่ **ไม่มีอยู่ในความเป็นจริง** เช่นได้ค่าที่ไม่ตรงกับ input ตัวใดเลย ขณะที่การโหวตระดับคำยังให้ค่าที่ถูกต้อง จึงต้องระวังว่าการโหวตระดับคำรักษาความสมบูรณ์ของข้อมูลได้ดีกว่า

**แนวข้อสอบที่อาจารย์ยืนยัน** คือน่าจะมีเรื่อง **TMR, non-SP และ masking** และย้ำว่าข้อสอบเป็นแบบ on-site เปิด book, net และ notebook ได้ ครอบคลุมทุกอย่างที่สอนมา
