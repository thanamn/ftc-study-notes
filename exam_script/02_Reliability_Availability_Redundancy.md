# Part 2 — FTC02 Fault Tolerant Systems (เรียงตามสไลด์)

สคริปต์ส่วนนี้เรียงตามลำดับสไลด์ของบท FTC02 เพื่อให้อ่านควบคู่กับไฟล์ PDF ได้ทันที ทุกหัวข้อมีตัวเลข `[สไลด์ N]` กำกับ

## ภาพรวมและคำถามตั้งต้น [สไลด์ 1–5]

สไลด์ที่สองบอกเนื้อหาของบทนี้ ได้แก่ introduction, terminology, failure rate และ reliability, ความสัมพันธ์กับ MTTF และ MTTR, availability, กลยุทธ์ในการจัดการ fault, เทคนิค redundancy และกรณีศึกษาต่าง ๆ เช่น RAID, TMR, Space Shuttle, software fault, process group, การสื่อสาร client-server และ checkpointing

สไลด์ที่สี่อธิบายว่า hardware, software และ network ไม่มีทางปลอดจากความล้มเหลวได้ทั้งหมด ดังนั้น fault tolerance จึงเป็นข้อกำหนดด้านคุณภาพที่ไม่ใช่เชิงหน้าที่ คือระบบต้องทำงานต่อได้แม้มี fault และควรทำโดยรบกวนผู้ใช้หรือผู้ดูแลน้อยที่สุด มีข้อสังเกตว่าละเอียดอ่อนว่า ระบบกระจายนั้นทนทานกว่า centralized system ได้ แต่ยิ่งมีเครื่องมากขึ้น โอกาสที่บางเครื่องจะเสียก็ยิ่งบ่อยขึ้น นี่คือความตึงเครียดที่แท้จริงของการออกแบบ

สไลด์ที่ห้าเป็นแผนภาพที่ควรจำครับ มันวางกล่องสามใบ กล่องแรกชื่อ Attributes มี availability, reliability, safety, confidentiality, integrity, maintainability พร้อมกรอบคำถามว่า What is a Dependable system? กล่องที่สองชื่อ Consequences มี fault, error, failure พร้อมคำถามว่า How to distinguish faults? และกล่องที่สามชื่อ Strategies มี fault prevention, fault tolerance, fault recovery, fault forecasting พร้อมคำถามว่า How to handle faults? สามคำถามนี้คือสามมุมของทั้งวิชา

## คำศัพท์และชนิดของ fault [สไลด์ 6-7]

สไลด์ที่หกให้สายพานพื้นฐานว่า Fault ก่อให้เกิด Error และ Error นำไปสู่ Failure โดย fault คือ defect ภายในระบบ error คือการเบี่ยงเบนจากพฤติกรรมที่คาดหมาย และ failure เกิดเมื่อระบบทำตามข้อกำหนดไม่ได้ สไลด์ที่เจ็ดจำแนก fault ตามเวลาเป็น permanent ซึ่งให้ error ที่เกิดซ้ำได้ และ soft fault ซึ่งแยกเป็น transient ที่เกิดครั้งเดียวและ intermittent ที่เกิดแบบสุ่มโดยปัจจัยยังไม่ชัด และมี operator error หรือความผิดพลาดของมนุษย์

## Failure mode ของระบบกระจาย [สไลด์ 8]

สไลด์ที่แปดเป็นตารางที่สำคัญและมักถูกมองข้ามครับ มันจำแนกชนิดของความล้มเหลวในระบบกระจาย มีห้ากลุ่มใหญ่ กลุ่มแรกคือ Crash failure ซึ่งหมายถึง server หยุดทำงาน แต่มันทำงานถูกต้องจนกระทั่งหยุด กลุ่มนี้ยังแยกย่อยเป็น Amnesia crash ที่สูญเสียประวัติทั้งหมดต้อง reboot ใหม่, Pause crash ที่ยังจำ state ก่อน crash ได้และกู้คืนได้ และ Halting crash ที่เป็น hardware failure ต้องเปลี่ยนหรือติดตั้งใหม่

กลุ่มที่สองคือ Omission failure ซึ่ง server ไม่ตอบคำขอที่เข้ามา แยกเป็น Receive omission ที่รับข้อความไม่ได้ และ Send omission ที่ส่งข้อความไม่ได้ กลุ่มที่สามคือ Timing failure ซึ่งคำตอบของ server อยู่นอกช่วงเวลาที่กำหนด กลุ่มที่สี่คือ Response failure ซึ่งคำตอบผิด แยกเป็น Value failure ที่ค่าผิด และ State transition failure ที่ server เบี่ยงจากเส้นทางการควบคุมที่ถูกต้อง และกลุ่มที่ห้าคือ Arbitrary failure ซึ่ง server อาจให้คำตอบอะไรก็ได้ในเวลาใดก็ได้ กลุ่มสุดท้ายนี้เองที่เราเรียกว่า Byzantine ในบทที่สาม ตารางนี้มีประโยชน์มากเพราะเวลาข้อสอบถามเรื่องชนิดของความล้มเหลวในระบบกระจาย เราสามารถไล่ตอบตามห้ากลุ่มนี้ได้

## Failure rate และเส้นโค้งอ่างอาบน้ำ [สไลด์ 9-10]

สไลด์ที่เก้านิยาม failure rate เป็นฟังก์ชันของเวลา วัดเป็นหน่วย FITS โดยหนึ่ง FIT คือความล้มเหลวหนึ่งครั้งต่อพันล้านชั่วโมง ตัวอย่างคือ NASA Flight เท่ากับ 1 FIT, คอมพิวเตอร์ทั่วไปประมาณหนึ่งแสนถึงหนึ่งล้าน FITs และชีวิตมนุษย์อายุแปดสิบห้าปีประมาณหนึ่งพันสามร้อยสี่สิบสาม FITs แผนภาพเป็น bathtub curve ที่มีแกนตั้งเป็น failure rate และแกนนอนเป็นเวลา แบ่งเป็นสามช่วงด้วยเส้นประ ช่วงแรก Infant mortality ที่ failure rate สูงแล้วลดลงพร้อมป้าย Early failures ช่วงกลาง Working life ที่มีป้าย Random failures และเส้น Overall curve ลาดลงต่ำสุด และช่วงท้าย Wearout ที่ failure rate เพิ่มขึ้นพร้อมป้าย Wearout failures

สไลด์ที่สิบเป็น bathtub curve ของซอฟต์แวร์ ซึ่งมีสามช่วงเช่นกัน แต่ชื่อต่างออกไปคือ Test และ Debug, Useful Life และ Obsolescence ที่น่าสนใจคือเส้นกราฟมีจุดกระโดดขึ้นหลายจุดที่กำกับว่า Upgrade สามครั้ง เพราะทุกครั้งที่เราอัปเกรดซอฟต์แวร์ ความน่าเชื่อถือมักลดลงชั่วคราวก่อนจะดีขึ้น ซึ่งไม่เหมือนฮาร์ดแวร์ที่ไม่มี upgrade

## การสร้างแบบจำลองความน่าเชื่อถือ [สไลด์ 11-13]

สไลด์ที่สิบเอ็ดแสดงแนวคิดที่สำคัญคือ เรามองระบบจริงเป็น physical schema แล้วแปลงเป็น reliability schema ตัวอย่างบนซ้ายเป็นระบบสูบน้ำที่มี pump และ filter ต่อกันตามลำดับทางกายภาพ เราจึงเขียน reliability schema เป็นกล่อง Pump ต่ออนุกรมกับกล่อง Filter ตัวอย่างล่างคือเครื่องกำเนิดไฟฟ้า A และ B ที่ต่อเข้าบัสเดียวกัน เราจึงเขียนเป็นกล่อง Generator A และ Generator B ต่อขนานกัน นี่คือทักษะสำคัญคือการมองระบบจริงแล้วแปลงเป็นไดอะแกรมความน่าเชื่อถือ

สไลด์ที่สิบสองย้ำนิยามว่า series system ทำงานเมื่อทุกชิ้นส่วนทำงาน และ parallel system ทำงานเมื่ออย่างน้อยหนึ่งชิ้นทำงาน สไลด์ที่สิบสามแสดงตัวอย่างระบบ series-parallel ที่ซับซ้อนขึ้น โดยมีสามบล็อกต่ออนุกรมกัน บล็อกแรกมีกล่องสองกล่องขนานกัน บล็อกที่สองมีสามกล่องขนานกัน และบล็อกที่สามมีสี่กล่องขนานกัน

## Minimal path set และ minimal cut set [สไลด์ 14-15]

สไลด์ที่สิบสี่และสิบห้าเป็นหัวข้อที่สำคัญมากและข้อสอบชอบออกครับ เราใช้ตัวอย่างระบบบริดจ์ที่มีห้ากล่องคือ 1, 2, 3, 4, 5 โดยกล่อง 3 อยู่ตรงกลางพาดขวาง Minimal path set หรือ MPS คือเซตย่อยของชิ้นส่วนที่ถ้าทำงานครบแล้วรับประกันว่าระบบทำงาน สำหรับบริดจ์นี้ เขียน MPS ออกมาเป็นสี่เซตคือ {1,2}, {1,3,5}, {4,3,2} และ {4,5} นั่นหมายความว่าเส้นทางสู่ความสำเร็จมีสี่ทาง

Minimal cut set หรือ MCS คือเซตย่อยที่ถ้าพังครบแล้วรับประกันว่าระบบพัง สำหรับบริดจ์นี้ได้สี่เซตคือ {1,4}, {2,5}, {1,3,5} และ {2,3,4} สังเกตว่าทั้ง MPS และ MCS มีสี่เซตเท่ากัน ซึ่งเป็นความสมมาตรที่สวยงามของเครือข่ายบริดจ์ เราสามารถคำนวณความน่าเชื่อถือของระบบได้จากการรวมเหตุการณ์ว่า MPS ทำงานครบ โดยใช้ inclusion และ exclusion จัดการส่วนทับซ้อน หรือคำนวณความไม่น่าเชื่อถือจากเหตุการณ์ว่า MCS พังครบก็ได้

## Reliability ของระบบ และวิธีเพิ่มความน่าเชื่อถือ [สไลด์ 16-19]

สไลด์ที่สิบหกบอกว่า สำหรับระบบที่ไม่มี fault tolerance ถ้าชิ้นส่วนใดพัง ระบบก็พังทั้งหมด failure rate ของระบบจึงเท่ากับผลรวมของ failure rate ของทุกชิ้นส่วน นี่คือหลักการที่อธิบายแบบฝึกหัด MTTF ของดิสก์ในบทที่หนึ่งด้วย

สไลด์ที่สิบเจ็ดนิยาม reliability ว่า ถ้าชิ้นส่วนทำงานที่เวลาเริ่มต้น R ของ t คือความน่าจะเป็นที่มันยังทำงานที่เวลา t และให้กฎ exponential ว่า R ของ t เท่ากับ e ยกกำลังลบ lambda t สไลด์ที่สิบแปดให้ค่า reliability ของระบบ series ว่าเท่ากับผลคูณของค่า reliability ของทุกชิ้นส่วน และสไลด์ที่สิบเก้าตั้งคำถามว่าจะทำให้ reliable ขึ้นได้อย่างไร โดยมีคันโยกคือลด failure rate, ลดจำนวนชิ้นส่วน, ลดเวลา และทางเลือกที่สี่คือเพิ่ม redundancy

## Redundancy และค่า reliability ของระบบ [สไลด์ 20-21]

สไลด์ที่ยี่สิบยกตัวอย่างที่ชัดเจนครับ ระบบที่มีกล่อง A ต่ออนุกรมกับกล่อง B ที่มีสองตัวขนานกัน แล้วต่ออนุกรมกับกล่อง C ค่า reliability ของ B แบบขนานคือหนึ่งลบ (หนึ่งลบ R_B) กำลังสอง ซึ่งเขียนได้อีกแบบว่าสอง R_B ลบ R_B กำลังสอง ดังนั้นค่า reliability ของระบบคือ R_A คูณวงเล็บนั้นคูณ R_C การตีความคือ redundancy ช่วยให้ระบบทนการพังของ B ได้หนึ่งตัว สไลด์ที่ยี่สิบเอ็ดสรุปเป็นสูตรทั่วไปว่า ระบบ series มีค่า R เท่ากับผลคูณของ R ทุกชิ้น และระบบ parallel มีค่า R เท่ากับหนึ่งลบผลคูณของ (หนึ่งลบ R) ทุกชิ้น

## การแจกแจงความน่าจะเป็น และ MTTF [สไลด์ 22-25]

สไลด์ที่ยี่สิบสองให้พื้นฐานเรื่องการแจกแจงความน่าจะเป็นครับ มีการแจกแจงสี่แบบคือ Uniform, Exponential, Normal และ Binomial โดยแสดงทั้งฟังก์ชันการแจกแจงสะสมหรือ CDF และฟังก์ชันความหนาแน่นหรือ pdf ตัวอย่างเช่น Exponential มี CDF ที่เพิ่มขึ้นแบบอิ่มตัวและ pdf ที่ลดลงแบบทวีคูณ สไลด์นี้มีไว้เพื่อให้เราเห็นว่ากฎ exponential เป็นเพียงหนึ่งในหลายแบบจำลอง

สไลด์ที่ยี่สิบสามเป็นสไลด์ที่ให้ความเข้าใจเชิงลึกครับ มันนิยาม reliability ว่าคือความน่าจะเป็นที่ระบบอยู่ในสถานะ Good ตลอดช่วงเวลาตั้งแต่ศูนย์ถึง t และให้สมการ R ของ t บวก dt เท่ากับ R ของ t คูณ (หนึ่งลบ z ของ t คูณ dt) โดย z ของ t นี้เรียกว่า hazard function เมื่อ hazard function คงที่เท่ากับ lambda เราจะได้ R ของ t เท่ากับ e ยกกำลังลบ lambda t ซึ่งหมายถึง failure rate ไม่ขึ้นกับอายุของระบบ สไลด์นี้ยังบอกว่า R ของ t เท่ากับหนึ่งลบ F ของ t โดยที่ F คือ CDF ของอายุระบบ หรือพูดอีกอย่างคือ unreliability นั่นเอง และให้สูตร MTTF ว่าเท่ากับอินทิกรัลจากศูนย์ถึงอนันต์ของ t คูณ f ของ t เทียบกับ t ซึ่งเท่ากับค่าคาดหมายของอายุ และเท่ากับอินทิกรัลของ R ของ t เทียบกับ t ซึ่งก็คือพื้นที่ใต้กราฟ reliability นั่นเอง

สไลด์ที่ยี่สิบห้าเป็นสไลด์ที่ให้เครื่องมือเปรียบเทียบความน่าเชื่อถือของสองระบบ ซึ่งอาจารย์มักใช้ถามครับ มีตัวชี้วัดหลายตัว Reliability difference คือ R2 ลบ R1 Reliability gain คือ R2 หาร R1 Reliability improvement factor หรือ RIF ซึ่งเท่ากับ (หนึ่งลบ R1 ที่เวลาภารกิจ) หาร (หนึ่งลบ R2 ที่เวลาภารกิจ) ตัวอย่างเช่น (หนึ่งลบ 0.9) หาร (หนึ่งลบ 0.99) เท่ากับสิบ หมายความว่าระบบที่สองลดความไม่น่าเชื่อถือลงสิบเท่า Reliability improvement index หรือ RII ซึ่งเท่ากับ log R1 หาร log R2 และยังมี mission time extension คือ T2 ลบ T1 และ mission time improvement factor คือ T2 หาร T1 ที่ระดับความน่าเชื่อถือ r_G ที่กำหนด ตัวชี้วัดเหล่านี้มีประโยชน์เวลาโจทย์ถามว่า "ระบบใหม่ดีขึ้นกี่เท่า" ซึ่งคำตอบไม่ใช่แค่ผลต่างของ R แต่ต้องดูที่ RIF

## Availability, MTTR และระบบสำรอง [สไลด์ 26-36]

สไลด์ที่ยี่สิบหกนิยามอัตราการซ่อม mu และ MTTR เท่ากับหนึ่งส่วน mu สไลด์ที่ยี่สิบเจ็ดนิยาม availability และให้แผนภาพแกนเวลาที่แสดงช่วง Normal system operation สลับกับช่วง failures โดยสูตรคือ availability เท่ากับ MTTF หารด้วย MTTF บวก MTTR สไลด์ที่ยี่สิบแปดบอกว่าระบบโทรศัพท์ต้องการสี่เก้า และระบบ high-reliability อาจต้องการเจ็ดเก้าขึ้นไป

สไลด์ที่ยี่สิบเก้าและสามสิบเป็นตารางที่น่าสนใจครับ สำหรับ availability แบบ series ที่มีสองชิ้นคือ A เท่ากับ A_x คูณ A_y ถ้าชิ้น X มี availability 99 เปอร์เซ็นต์ หรือสองเก้า และชิ้น Y มี 99.99 เปอร์เซ็นต์ หรือสี่เก้า เมื่อรวมกันแบบ series จะได้ 98.99 เปอร์เซ็นต์ ซึ่งต่ำกว่าทั้งสองชิ้น นี่คือบทเรียนว่า series ลด availability ลง ส่วน availability แบบ parallel ที่มีสองชิ้นคือ A เท่ากับหนึ่งลบ (หนึ่งลบ A_x) กำลังสอง ถ้าชิ้น X มีสองเก้า สองชิ้นขนานกันได้สี่เก้า และสามชิ้นขนานกันได้ถึงหกเก้า โดย downtime ลดจากสามวันครึ่งต่อปีเหลือห้าสิบสองนาทีเหลือสามสิบเอ็ดวินาที นี่คือบทเรียนว่า parallel เพิ่ม availability อย่างมาก

สไลด์ที่สามสิบเอ็ดถึงสามสิบห้าให้สูตรสำหรับระบบที่มีชิ้นส่วนสำรองครับ ถ้ามีเครื่อง n เครื่อง แต่ละเครื่องมี availability a และมีสำรอง s เครื่อง จำนวนโหมดความล้มเหลว f คือจำนวนวิธีเลือก s บวกหนึ่ง เครื่องจาก n เครื่อง ความน่าจะเป็นที่ระบบพังคือ F เท่ากับ f คูณ (หนึ่งลบ a) ยกกำลัง s บวกหนึ่ง และ availability เท่ากับหนึ่งลบ F กรณี special ที่ควรจำคือ single spare ซึ่ง f เท่ากับ n คูณ (n ลบหนึ่ง) หารสอง ตัวอย่างเครื่องห้าเครื่องมีสำรองหนึ่งเครื่อง f เท่ากับสิบ และ availability เท่ากับหนึ่งลบสิบคูณศูนย์จุดศูนย์หนึ่งกำลังสอง ซึ่งเท่ากับ 0.999 หรือสามเก้า และตัวอย่างเครื่องหกเครื่องมีสำรองสองเครื่อง f เท่ากับยี่สิบ และ availability เท่ากับหนึ่งลบยี่สิบคูณศูนย์จุดศูนย์หนึ่งกำลังสาม เท่ากับ 0.99998

สไลด์ที่สามสิบหกให้ตารางที่ต้องตอบให้ได้ครับ มันถามว่าเมื่อ reliability คงที่และ maintainability ลดลง availability เป็นอย่างไร คำตอบคือลดลง เพราะ maintainability ลดหมายถึงเวลาซ่อมนานขึ้น และสไลด์ย้ำว่าสาเหตุที่ availability ขึ้นกับ maintainability ด้วยก็เพราะ availability เป็นฟังก์ชันของทั้งสองอย่าง

## TMR และการเปรียบเทียบ PS กับ SP [สไลด์ 38-41]

สไลด์ที่สามสิบแปดและสามสิบเก้าเป็นแบบฝึกหัด TMR ที่เรารู้จักแล้วครับ โจทย์ให้หา reliability ของระบบ TMR โดย U1, U2 และ U3 มีค่าเท่ากับ R_U และ voter มีค่า R_V แผนภาพคือ input แยกสามทางเข้าหน่วยทั้งสาม แล้วรวมเข้า voter แล้วออกขวา คำตอบคือ R_tmr เท่ากับ (R_U กำลังสาม บวก สาม R_U กำลังสอง คูณ (หนึ่งลบ R_U)) คูณ R_V ซึ่งจัดรูปได้ (สาม R_U กำลังสอง ลบ สอง R_U กำลังสาม) คูณ R_V วงเล็บคือความน่าจะเป็นที่อย่างน้อยสองในสามหน่วยทำงาน

สไลด์ที่สี่สิบและสี่สิบเอ็ดเป็นแบบฝึกหัดเปรียบเทียบ PS กับ SP ครับ แบบแผน PS คือทำสำเนา A สองชุดขนานกัน ต่ออนุกรมกับสำเนา B สองชุดขนานกัน ส่วนแบบแผน SP คือต่อ A อนุกรม B สองเส้น แล้ววางสองเส้นนั้นขนานกัน คำตอบคือ R_PS เท่ากับ [หนึ่งลบ (หนึ่งลบ R_A) กำลังสอง] คูณ [หนึ่งลบ (หนึ่งลบ R_B) กำลังสอง] ซึ่งถ้า R_A เท่ากับ R_B เท่ากับ R จะได้ R กำลังสี่ ลบ สี่ R กำลังสาม บวก สี่ R กำลังสอง และ R_SP เท่ากับ [หนึ่งลบ (หนึ่งลบ R_A R_B)(หนึ่งลบ R_A R_B)] ซึ่งได้ สอง R กำลังสอง ลบ R กำลังสี่ และสไลด์ย้ำบรรทัดสุดท้ายว่า R_PS มากกว่า R_SP นั่นคือ replicate ที่ระดับล่างก่อนดีกว่าเสมอ

## ระบบที่มีความน่าเชื่อถือสูง กลยุทธ์ และ redundancy [สไลด์ 42-45]

สไลด์ที่สี่สิบสองแบ่งระบบที่มีความน่าเชื่อถือสูงเป็นสามกลุ่มครับ กลุ่ม long-life system เช่นยานอวกาศที่ต้องใช้งานหลายปี ลักษณะคือ fail-slow, rugged และ high-reliability และใช้ replication, error coding, monitoring และ shielding กลุ่ม safety-critical system เช่น flight control, ระบบปิดเครื่องปฏิกรณ์นิวเคลียร์ และ medical monitoring ลักษณะคือ fail-safe, sound และ high-integrity และใช้ replication with voting, time redundancy และ design diversity กลุ่ม non-stop system เช่นชุมสายโทรศัพท์ ลักษณะคือ fail-soft, robust และ high-availability และใช้ hardware และ information redundancy, backup scheme, hot-swap และ recovery

สไลด์ที่สี่สิบสามให้กลยุทธ์จัดการ fault สี่แบบคือ fault avoidance ซึ่งป้องกัน fault เข้ามาในขั้นออกแบบ, fault removal ซึ่งหาข้อบกพร่องก่อนเข้าใช้งาน, fault detection ซึ่งตรวจจับระหว่างใช้งาน และ fault tolerant ซึ่งออกแบบให้ทน fault สไลด์ที่สี่สิบสี่ให้เทคนิค redundancy สามแบบคือ hardware redundancy ซึ่งทำสำเนาและเปรียบเทียบ ตรวจได้ทั้ง permanent และ temporary, information redundancy ซึ่งใช้รหัสและใช้ฮาร์ดแวร์น้อยกว่า และ temporal redundancy ซึ่งทำซ้ำและเปรียบเทียบ แต่ใช้ได้กับ transient fault เท่านั้น และสไลด์ที่สี่สิบห้าให้แนวทางสถาปัตยกรรมตั้งแต่ simplex ไปจนถึง dual แบบ identical และ dissimilar และ N-way redundant

## RAID และ TMR [สไลด์ 46-47]

สไลด์ที่สี่สิบหกอธิบาย RAID หรือ redundant array of independent disks โดยแสดงสอง level ครับ Level 1 คือ Mirroring และ Duplexing ซึ่งเขียนข้อมูลเดียวกันลงดิสก์สองลูกพร้อมกัน เห็นได้จากแผนภาพที่มีดิสก์คู่ A B C D แล้วมีเครื่องหมายเท่ากับและป้าย Mirroring และ Level 2 คือ Hamming Code ECC ที่เก็บข้อมูลสี่ word ไว้ในดิสก์สี่ลูก แล้วเก็บรหัส ECC ไว้ในดิสก์อีกสามลูก สไลด์ปิดท้ายว่า RAID ถูกจำแนกเป็นหลาย level ได้แก่ 0, 1, 2, 3, 4, 5, 6, 10 และ 50 โดยแต่ละ level ให้ระดับ fault tolerance ต่างกัน

สไลด์ที่สี่สิบเจ็ดแสดง Failure Masking โดย TMR ครับ แผนภาพ (a) เป็นวงจรปกติที่มี A ต่อ B ต่อ C ส่วนแผนภาพ (b) เป็นวงจร TMR ที่ทำสำเนา A สามชุดคือ A1, A2, A3 แล้วป้อนเข้า voter สามชุด V1, V2, V3 แบบ fully-crossed แล้วจึงเข้าชุด B ที่ทำสำเนาสามชุด และต่อไปเรื่อย ๆ จนถึง C วิธีนี้ทำให้ทั้งเส้นทางมี redundancy ไม่ใช่แค่จุดเดียว

## Space Shuttle และ Software Fault Tolerance [สไลด์ 48-50]

สไลด์ที่สี่สิบแปดอธิบายระบบ Space Shuttle ที่ใช้ห้าเครื่องครับ ในช่วงวิกฤตอย่าง boost, re-entry และ landing เครื่องสี่ในห้าทำงานแบบ NMR เมื่อตรวจพบความล้มเหลวเครื่องที่เสียจะถูกสลับออกเหลือ TMR เครื่องที่ห้าทำงานไม่สำคัญแบบ simplex แต่มี diverse software และทนได้สองเครื่องก่อนจะกลายเป็น duplex

สไลด์ที่สี่สิบเก้าอธิบาย software fault ว่ามาจาก specification error, design error, coding error, integration error และ runtime error และย้ำว่า software failure มัก deterministic สไลด์ที่ห้าสิบอธิบาย N-version programming ซึ่งใช้ implementation หลายชุดของ specification เดียวกัน รันแล้วเปรียบเทียบ ถ้าสองชุดไม่ตรงกันอาจรันซ้ำหรือตัดสินว่าใครผิด และถ้ามีสามชุดขึ้นไปก็โหวตได้

## การบ้าน HW02 [สไลด์ 51]

สไลด์สุดท้ายเป็นการบ้านที่ให้แบบแผนสองแบบชื่อ PP และ AP ซึ่งเป็นตารางสามคูณสามของ A, B และ C โดยแบบ PP มีความเชื่อมโยงที่ทำให้เกิดโครงข่ายแบบบริดจ์ ส่วนแบบ AP มีโครงสร้างที่แต่ละคอลัมน์ต่ออนุกรมกันและแต่ละแถวต่ออนุกรมกันเป็นตาราง งานคือหา MPS และ MCS ของแต่ละแบบ หาค่า reliability ของทั้งสอง และเมื่อให้แต่ละ subsystem เท่ากับ R ให้หาค่า reliability และบอกว่าแบบไหนดีกว่า วิธีทำคือเริ่มจากหา MPS โดยไล่ทุกเส้นทาง แล้วใช้ inclusion และ exclusion หรือลดรูปเป็น series-parallel จากนั้นแทนค่า R ไม่มี shortcut พิเศษนอกจากฝึกทำจนชำนาญ


## จากคำบรรยายในห้อง [insights]

> ส่วนนี้มาจาก transcript เสียงบรรยาย (ถอดด้วย Whisper) ข้อความอาจมีเพี้ยน แต่ประเด็นที่อาจารย์เน้นชัดเจน [ไม่แน่ใจ] = จุดที่เสียงไม่ชัด

อาจารย์ย้ำนิยามของ fault tolerance ในแบบของตัวเองว่า **เป็นความสามารถของระบบที่จะทำงานต่อให้อยู่ในลักษณะ error-free แม้ว่าจะมี fault เกิดขึ้น** คือเรายอมให้ fault เกิดได้ แต่ทำให้ error ไม่ส่งผลต่อ operation และเน้นว่าเป็น **non-functional requirement** ที่ระบบควรมี โดย fault tolerance ที่ดีคือระบบที่ **ผู้ใช้หรือผู้ดูแลต้องเข้าไปยุ่งน้อยที่สุด** ประเด็นนี้ช่วยเวลาตอบคำถามเชิงแนวคิด เพราะมันจับคู่ "มี fault ได้ แต่ operation ต้องถูก"

**ลำดับการวิเคราะห์ที่อาจารย์ใช้** คือดู attributes ก่อนว่าอะไรเป็นสาเหตุของ fault/error/failure แล้วดูว่า consequence อยู่ตรงไหน แล้วจึงกำหนด strategy จึงไม่ใช่ท่องสามคำแยกกัน แต่เป็นการไล่จากคุณสมบัติไปสู่ผลกระทบไปสู่วิธีจัดการ

**การสร้าง reliability model** อาจารย์อธิบายจากระบบจริง เช่นระบบสูบน้ำที่มี pump แล้วผ่าน filter ตามลำดับทางกายภาพ จึงได้เป็น series reliability เท่ากับผลคูณของ pump กับ filter และตัวอย่างสายพานที่มีสองหน่วยทำงานเหมือนกันเพื่อป้องกัน จึงได้เป็น parallel redundancy วิธีคิดคือ "ดู physical model แล้วแปลงเป็น block diagram" และเขาย้ำว่า reliability block diagram มีวิธีต่อพื้นฐานแค่สองแบบคือ series กับ parallel เท่านั้น

**ทำไม R_PS ถึงมากกว่า R_SP** อาจารย์ไม่ได้ให้แค่ผลลัพธ์ แต่ให้เหตุผลผ่าน **minimum path set** ว่าฝั่ง PS มีเส้นทางสู่ความสำเร็จมากกว่า จึงทนกว่า ขณะที่ฝั่ง SP มีจุดที่ถ้าพังแล้วระบบทำต่อไม่ได้เลย ซึ่งเป็นวิธีคิดที่ใช้ตอบโจทย์ได้ดีกว่าการแทนตัวเลข

**R1 กับ R2 อันไหนดีกว่ากันขึ้นกับ mission time** อาจารย์ย้ำว่าระบบหนึ่งอาจ reliable กว่าในช่วงเวลาสั้น แต่อีกอันดีกว่าในช่วงยาว ดังนั้นคำตอบว่า "อันไหนดีกว่า" ต้องขึ้นกับว่า mission ของเรายาวแค่ไหน ถ้า mission สั้นเลือกตัวที่สูงกว่าในช่วงนั้น ถ้า mission ยาวเลือกอีกตัว

**ความสัมพันธ์ระหว่าง MTBF (หรือ MTTF) กับ availability** อาจารย์พูดหลายรอบว่า component ที่ **ล้มบ่อยแต่ซ่อมเร็ว** อาจมี availability ดีได้ และ component ที่ล้มไม่บ่อยแต่ **ซ่อมนาน** กลับมี availability แย่ นี่คือเหตุผลว่าทำไม availability จึงเป็นฟังก์ชันของทั้ง reliability และ maintainability ซึ่งเป็นประเด็นที่โจทย์ชอบถาม

หมายเหตุ: เฉลย TMR ที่อาจารย์บอกว่าจะแจกเพิ่ม และการบ้านมีสองชุดที่เน้นการคำนวณ reliability (ชุดที่สองคือ PP กับ AP scheme ให้เขียน reliability expression ของทั้งคู่แล้วเทียบ) [ไม่แน่ใจ: รายละเอียดวันส่งงาน]
