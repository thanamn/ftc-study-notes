# Part 8 — ซ้อมโจทย์ แผ่นสูตร และการตรวจช่องโหว่

## ก่อนอื่น มาวางกลยุทธ์ในห้องสอบกันก่อน

ข้อสอบของเราเป็นแบบเปิดหนังสือ เปิดโน้ต และเปิดอินเทอร์เน็ต ใช้เวลาสามชั่วโมง นี่เปลี่ยนวิธีเตรียมตัวของเราไปอย่างมีนัยสำคัญครับ เพราะเราไม่จำเป็นต้องท่องจำทุกอย่างแบบปิดหนังสือ สิ่งที่เราต้องทำได้จริง ๆ คือ เมื่ออ่านโจทย์แล้วเข้าใจว่ามันกำลังถามเรื่องอะไร แล้วรู้ว่าจะเปิดไปหาข้อมูลส่วนไหน และต้องใช้สูตรหรือขั้นตอนอะไร

ผมจึงอยากให้คุณตั้งเป้าสามระดับสำหรับทุกหัวข้อ ระดับแรกคือ **รู้แบบไม่ต้องคิด** นั่นคือคำนิยามและกฎบรรทัดเดียวที่ทำให้คุณจำแนกโจทย์ได้ทันที เช่นรู้ว่า totally self checking หมายถึงอะไร รู้เงื่อนไข n มากกว่าหรือเท่ากับสาม m บวกหนึ่ง และรู้สูตร series กับ parallel ระดับที่สองคือ **derive ได้** นั่นคือกระบวนการทีละขั้นที่คุณจะลงมือทำจริงในห้องสอบ เช่นการหารยาวของ cyclic code การวาดรอบของ Oral Message และการแยกด้วย keystone ของวงจรบริดจ์ ระดับที่สามคือ **เปิดดูได้** นั่นคือรายการยาว ๆ รายละเอียดในตาราง และถ้อยคำเต็มของทฤษฎีบทระดับรอง ซึ่งเราไม่จำเป็นต้องจำได้ทั้งหมด แต่ต้องรู้ว่ามันอยู่ตรงไหนในโน้ต

เวลาอ่านโจทย์ทุกข้อ ให้ถามตัวเองด้วยคำถามสามข้อนี้ครับ มันถามเรื่อง **หาปริมาณ** เช่น reliability, availability หรือ probability หรือมันถามเรื่อง **แยกประเภท** เช่น FS หรือ ST หรือ TSC, consistent หรือ inconsistent cut, และชนิดของ fault หรือมันถามเรื่อง **ออกแบบหรือบรรยายขั้นตอน** เช่น Oral Message, cyclic encoding หรือ checker เมื่อเราจำแนกได้แล้ว การเลือกเครื่องมือก็จะตามมาเอง

## โยงโจทย์จากข้อสอบเก่ากับเนื้อหา

ทีนี้เรามาดูข้อสอบเก่าทีละข้อว่าโยงกับบทไหน และควรตอบอย่างไร

ข้อ 1.1 ถามเรื่อง **Liveness และ Safety ในมุมมองของ FTC** อยู่ที่บทที่หนึ่ง ตอบว่าสิ่งนี้เทียบได้กับ safety property ที่บอกว่า "จะไม่มีอะไรแย่เกิดขึ้น" ซึ่งตรงกับ safety attribute และ liveness property ที่บอกว่า "จะต้องมีสิ่งดีเกิดขึ้นในที่สุด" ซึ่งตรงกับ reliability และ availability และให้ชี้ความตึงเครียดว่าบางระบบทำ safety ได้ด้วยการหยุดทำงาน ซึ่งแลกมาด้วย liveness ผมขอติดธงว่านี่เป็นการตีความ เพราะสไลด์ไม่ได้เขียนถ้อยคำนี้ตรง ๆ

ข้อ 1.2 ถามเรื่อง **Threat ของระบบธนาคารออนไลน์** อยู่ที่บทที่หนึ่ง ให้ตอบตามสายพาน โดยแฮกเกอร์หรือความผิดพลาดของมนุษย์คือ fault นำไปสู่ error ในสภาพข้อมูล และกลายเป็น failure แล้วโยงผลกระทบกับ attributes ทั้ง integrity, confidentiality, availability และ reliability และโยงการป้องกันกับ means ทั้ง error control, self-checking, fault masking, fail-safe และ data security

ข้อ 1.3 ถามว่า **ถ้าโปรแกรมล้มเหลวก่อนสำเร็จ นั่นคือ MTTF น้อยกว่าเวลาที่ระบบต้องทำงาน ควรแก้อะไร ที่ไม่ใช่เพิ่ม reliability** อยู่ที่บทที่หนึ่งและสอง ตอบว่าต้องเปลี่ยนสถาปัตยกรรม ไม่ใช่ตัวชิ้นส่วน โดยเพิ่ม redundancy เพิ่ม fault tolerance ผ่าน checkpointing และ rollback ปรับปรุง maintainability ให้ MTTR ต่ำลงเพื่อเพิ่ม availability แม้ MTTF เท่าเดิม หรือย่อระยะเวลาภารกิจ

ข้อ 1.4 ถามว่า **Fail-Safe, Self-Checking และ Recovery ไปวางตรงไหน** บนแผนภาพ design techniques อยู่ที่บทที่หนึ่งและเจ็ด คำตอบคือ self-checking อยู่ที่โซนต้นของ error, fault masking อยู่ระหว่าง fault กับ error, fail-safe อยู่ที่รอยต่อระหว่าง error กับ failure และ recovery คือการตอบสนองหลังตรวจพบ failure

ข้อ 1.5 เป็นเรื่อง **ตาราง recovery และการจับคู่เวลาเท่ากันกับไม่เท่ากัน** อยู่ที่บทที่สี่ อย่างที่ผมได้ติดธงไว้ ตีความว่าเวลาเท่ากันคือ coordinated หรือ synchronous rollback ที่ทุก process ย้อนไปยัง recovery line เดียวกัน และเวลาไม่เท่ากันคือ uncoordinated หรือ asynchronous rollback ที่แต่ละ process ย้อนอย่างอิสระ และในคำตอบควรระบุความต่างระหว่าง consistent, strongly consistent และ inconsistent cut ด้วย

ข้อ 1.6 เป็นเรื่อง **กริด Hamming distance** อยู่ที่บทที่ห้า ให้ตอบด้วยกฎระยะห่างสามข้อ คือตรวจจับต้องมีระยะอย่างน้อย s บวกหนึ่ง แก้ไขต้องมีระยะอย่างน้อยสอง t บวกหนึ่ง และทำพร้อมกันต้องมีระยะอย่างน้อยสี่

ข้อ 2 ถามเรื่อง **หาความน่าจะเป็นของเครือข่ายสี่แบบ** อยู่ที่บทที่สอง ให้เขียนสูตร series, parallel และ bridge ด้วย keystone หรือพหุนาม R ยกกำลังหก ลบ สาม R ยกกำลังห้า บวก R ยกกำลังสี่ บวก สอง R ยกกำลังสาม จากนั้นข้อ 2.5 ให้ตั้งอสมการว่าเครือข่ายแบบ bridge มีค่ามากกว่า 1.2 เท่าของเครือข่ายแบบ series แล้วแก้หาค่า R และข้อ 2.6 เลือกเครือข่ายที่ดีที่สุด จำไว้ว่าคำตอบแบบ "เพิ่ม redundancy ไว้ก่อนเสมอ" นั้นไม่จริงเมื่อค่า R ต่ำ

ข้อ 3 ถามเรื่อง **เจ็ด node ซื่อสัตย์ห้าคนกบฏสองคน** อยู่ที่บทที่สาม ให้ตรวจว่า n มากกว่าหรือเท่ากับสาม m บวกหนึ่ง จากนั้นบรรยายรอบ OM ของสอง, OM ของหนึ่ง และ OM ของศูนย์ แล้ววาดตาราง vector พร้อมคอลัมน์เสียงข้างมาก ซึ่งจะได้ว่าทุกคนได้ค่า A

ข้อ 4 ถามเรื่อง **สัญกรณ์ (n, M, d), Berger code และการหารยาว** อยู่ที่บทที่ห้า โดย n คือความยาว M คือจำนวน codeword และ d คือ minimum distance ส่วน Berger code คือการนับจำนวนหนึ่งในข้อมูลเป็นเลขฐานสองแล้วต่อท้ายด้วย complement และการหารยาวคือ systematic cyclic encoding ที่เลื่อนข้อมูลไปซ้าย n ลบ k แล้วหารด้วย generator แล้วต่อ remainder

ข้อ 5 ถามเรื่อง **FS, ST, TSC และ SFS** อยู่ที่บทที่หก ให้สร้าง truth table ระบุ codeword กับ non-codeword ใส่ fault แล้วตรวจว่ามี codeword ที่ผิดโผล่หรือไม่เพื่อตัดสิน FS และตรวจว่ามี input ที่มองเห็น fault หรือไม่เพื่อตัดสิน ST

ข้อ 6 ถามเรื่อง **notation ของ code ที่มีความยาวหก และโจทย์ C stuck-at-1** อยู่ที่บทที่ห้าและหก ส่วนแรกคือการนับ codeword และคำนวณ pairwise distance เพื่อหา d แล้วเขียนเป็น (n, M, d) ส่วนที่สองใช้วิธีเดียวกับข้อ 5 แต่กับวงจรลอจิก

## ตารางคำที่มักสับสน

ผมอยากให้ท่องคู่คำเหล่านี้พร้อมความต่างสั้น ๆ เพราะข้อสอบชอบสลับครับ reliability กับ availability คือระยะเวลาเทียบกับเปอร์เซ็นต์เวลา fault removal กับ fault tolerance คือการลดจำนวนความผิดพลาดเทียบกับการทำงานทั้งที่ยังมีมัน fault avoidance กับ fault masking คือตอนออกแบบเทียบกับตอนรัน error กับ failure คือสภาพภายในเทียบกับบริการที่ส่งออก detect กับ correct คือระยะอย่างน้อย s บวกหนึ่งเทียบกับสอง t บวกหนึ่ง lost กับ delayed และ orphan และ duplicate message คือสี่ชนิดที่ต้องแยก consistent กับ strongly consistent cut คือมี orphan หรือไม่เทียบกับมี message ค้างหรือไม่ Fault Secure กับ Self Testing Code Disjoint กับ Error Secure TMR กับ NMR bit voting กับ word voting และ forward กับ backward recovery

## แผ่นสูตรที่อ่านออกเสียงได้

ลองทบทวนสูตรทั้งหมดด้วยการอ่านออกเสียงครับ ค่าความน่าเชื่อถือ R ของ t เท่ากับ e ยกกำลังลบ lambda t, MTTF เท่ากับหนึ่งส่วน lambda และเท่ากับพื้นที่ใต้กราฟของ R, ค่า maintainability M ของ t เท่ากับหนึ่งลบ e ยกกำลังลบ mu t, MTTR เท่ากับหนึ่งส่วน mu และ availability เท่ากับ MTTF หารด้วย MTTF บวก MTTR

สำหรับโครงสร้าง ระบบ series มีค่า R เท่ากับผลคูณของ R ของทุกชิ้น และ availability เท่ากับ A sub x คูณ A sub y ส่วนระบบ parallel มีค่า R เท่ากับหนึ่งลบผลคูณของ (หนึ่งลบ R) และ availability ของสองกิ่งเท่ากับหนึ่งลบ (หนึ่งลบ A sub x) ยกกำลังสอง สำหรับระบบที่มีชิ้นส่วนสำรอง availability เท่ากับหนึ่งลบ f คูณ (หนึ่งลบ a) ยกกำลัง s บวกหนึ่ง โดย f เท่ากับจำนวนวิธีเลือก s บวกหนึ่ง จาก n

สำหรับ TMR ค่า R เท่ากับ (สาม R sub m กำลังสอง ลบ สอง R sub m กำลังสาม) คูณ R sub V โดย TMR ดีกว่า simplex เมื่อ R sub m มากกว่าครึ่ง ค่า MTTF เท่ากับห้าส่วนหก lambda และเงื่อนไข voter คือ R sub V มากกว่าหนึ่งหารด้วย (สาม R sub m ลบ สอง R sub m กำลังสอง) สำหรับระบบที่ไม่ใช่ series-parallel เราใช้ conditioning บน keystone และพหุนามของ bridge คือ R ยกกำลังหก ลบ สาม R ยกกำลังห้า บวก R ยกกำลังสี่ บวก สอง R ยกกำลังสาม

สำหรับ Byzantine เงื่อนไขคือ n มากกว่าหรือเท่ากับสาม m บวกหนึ่ง จำนวน message โตเป็น n ยกกำลัง m และการนับ process คือ k บวกหนึ่ง สำหรับ silent, สอง k บวกหนึ่ง สำหรับ arbitrary และสาม k บวกหนึ่ง สำหรับ colluding

สำหรับ coding กฎคือตรวจจับด้วยระยะอย่างน้อย s บวกหนึ่ง แก้ไขด้วยระยะอย่างน้อยสอง t บวกหนึ่ง และ SEC-DED ด้วยระยะอย่างน้อยสี่ สัญกรณ์ (n, M, d) และ code rate เท่ากับ log ฐาน q ของ M หารด้วย n สำหรับ cyclic code ขนาด (n, k) นั้น generator polynomial มีดีกรี n ลบ k และต้องหาร x ยกกำลัง n ลบหนึ่งลงตัว สำหรับ Berger code จำนวนบิตตรวจสอบคือ ceiling ของ log ฐานสองของ (k บวกหนึ่ง) และความยาวรวมคือ k บวก c และสำหรับ low-cost residue code นั้น A เท่ากับสองยกกำลัง a ลบหนึ่ง

## การตรวจช่องโหว่ของสคริปต์

ผมได้ตรวจสคริปต์นี้เทียบกับเอกสารทั้งหมดแล้ว และอยากสรุปให้คุณทราบครับ ในด้านความครอบคลุม เนื้อหา FTC01 ถึง FTC07 ครบทุกสไลด์เชิงเนื้อหา รวมถึงหัวข้อที่อาจดูเป็นรอง เช่นลักษณะของระบบ resilient, RAM และ RMA, การบำรุงรักษาทั้งสี่แบบ, ตารางจำแนก failure และ error, RAID, ระบบ Space Shuttle, software fault tolerance, blockchain, สถานการณ์ client-server ทั้งห้า, ตระกูล recovery ทั้งหมด, รหัสตรวจและแก้ข้อผิดพลาดทั้งหมด และ checker ทุกชนิด

ในด้านขอบเขต สิ่งที่อยู่นอกข้อสอบครั้งนี้คือบทเรียน TDC Testing Digital Circuits ทั้งสี่บท และเนื้อหาที่สไลด์กำกับว่า out-of-scope เช่น ISBN code, data compression, cryptography และ information theory ในระดับลึก

และในด้านความไม่แน่นอน ผมได้ติดธงจุดที่ต้องระวังไว้หลายแห่ง หนึ่ง เรื่อง liveness กับ safety นั้นสไลด์ไม่ได้เขียนตรง ๆ ผมจึงตีความ สอง โจทย์เรื่อง "เวลาเท่ากันหรือไม่เท่ากัน" ของ recovery นั้นกำกวม ผมจึงให้สองการตีความ สาม โจทย์กริดที่เกี่ยวกับ Hamming distance เท่ากับหนึ่งนั้นน่าจะเป็นความจำที่เพี้ยน ผมจึงตอบด้วยกฎระยะห่างแทน และสี่ โจทย์ "code length เท่ากับหก" นั้นกำกวม ผมจึงแนะนำให้แสดงตาราง pairwise distance เพื่อความปลอดภัย นอกจากนี้ บท FTC01 และ FTC02 นั้นไม่มี transcript ที่เชื่อถือได้เพราะเสียงบันทึกมีเสียงก้องมาก ผมจึงอ้างอิงจากสไลด์เท่านั้น ซึ่งก็เพียงพอ

สิ่งที่ควรเปิดดูระหว่างสอบมากกว่าท่องจำคือรายการยาว ๆ เช่นการจำแนกการบำรุงรักษาสี่แบบ ลักษณะของ resilient system สี่ข้อ สถานการณ์ client-server ห้าข้อ ประเภท message ห้าชนิด และรายละเอียดของ checker ชนิดต่าง ๆ ส่วนสิ่งที่ต้องจำแบบไม่ต้องคิดคือกฎระยะห่าง Hamming สูตร series, parallel และ TMR เงื่อนไข n มากกว่าหรือเท่ากับสาม m บวกหนึ่ง และนิยามของ FS, ST, TSC และ SFS

## เช็กลิสต์ก่อนสอบ

สุดท้ายนี้ ลองทดสอบตัวเองด้วยการอธิบายออกเสียงแปดอย่างนี้ ถ้าทำได้ครบโดยไม่เปิดโน้ต แสดงว่าคุณพร้อมแล้ว อย่างแรก อธิบายสายพาน fault ไป error ไป failure พร้อมตัวอย่างธนาคารออนไลน์ อย่างที่สอง เขียนสูตร reliability series, parallel, TMR และ bridge พร้อมอธิบายว่าทำไม TMR ดีกว่า simplex ก็ต่อเมื่อ R มากกว่าครึ่ง อย่างที่สาม อธิบาย OM ของสองสำหรับเจ็ด node กับกบฏสองตัวและวาดตารางเสียงข้างมาก อย่างที่สี่ อธิบาย consistent, strongly consistent และ inconsistent cut พร้อมยกตัวอย่าง orphan message อย่างที่ห้า รันการหารยาวของ cyclic code ขนาด (7, 4) จากข้อมูล 0101 ให้ได้ อย่างที่หก คำนวณ Berger check ของคำหนึ่งให้ได้ อย่างที่เจ็ด อธิบาย FS, ST, TSC และ SFS พร้อมตรวจ input ชุดหนึ่ง และอย่างที่แปด วาดแผนที่ Fault Avoidance, Fault Masking และ Fault Tolerance แล้ววาง self-checking, recovery และ fail-safe ให้ถูกที่

ถ้าคุณจะฟังสคริปต์นี้ซ้ำตอนเดินทาง ผมแนะนำให้เริ่มจากส่วน "สรุปสิ่งที่ต้องจำ" ท้ายแต่ละบทก่อน แล้วค่อยกลับไปฟังเนื้อหาเต็มเฉพาะส่วนที่ยังไม่แม่น เมื่อทำได้อย่างนี้ คุณจะค่อย ๆ สร้างดัชนีในหัวขึ้นมา และแม้ว่าในห้องสอบคุณจะเปิดโน้ตได้ แต่ความมั่นใจที่แท้จริงจะมาจากการที่คุณรู้ว่าตัวเองกำลังหาอะไร อยู่ตรงไหนของแผนที่ และจะใช้มันอย่างไร ขอให้โชคดีในการสอบครับ
