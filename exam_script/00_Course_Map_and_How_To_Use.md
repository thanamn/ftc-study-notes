# FTC — บทนำ แผนที่รายวิชา และวิธีใช้สคริปต์นี้

สวัสดีครับ ยินดีต้อนรับสู่สคริปต์ติวสอบวิชา Fault Tolerant Computing ครับ ก่อนที่เราจะเริ่มลงรายละเอียด ผมอยากใช้เวลาสักครู่เพื่อปูภาพรวมก่อนว่า วิชานี้พูดถึงอะไร ทำไมเราต้องเรียนมัน และเนื้อหาทั้งเจ็ดบทเชื่อมกันอย่างไร เพราะถ้าเราเห็นแผนที่ของทั้งวิชาก่อน เวลาลงไปอ่านรายละเอียดในแต่ละบท เราจะรู้ว่าตัวเองกำลังอยู่ตรงไหนของเรื่องราวใหญ่ และรู้ว่าสิ่งที่กำลังเรียนมันไปเชื่อมกับอะไร

## วิชานี้เกี่ยวกับอะไร และทำไมเราต้องสนใจ

ลองนึกภาพระบบคอมพิวเตอร์ที่เราใช้งานอยู่ทุกวันครับ เช่นระบบธนาคารออนไลน์ ระบบนำทางในรถยนต์ หรือแม้แต่เครื่องกระตุ้นหัวใจที่ฝังอยู่ในร่างกายผู้ป่วย มนุษย์เราพึ่งพาระบบเหล่านี้มากขึ้นเรื่อย ๆ และเมื่อเราพึ่งพาอะไร เราก็ต้องการให้มัน "เชื่อถือได้" แต่คำว่าเชื่อถือได้ในที่นี้ไม่ได้หมายถึงแค่เครื่องเปิดติดหรือไม่ติดเท่านั้น มันกว้างกว่านั้นมาก

วิชา Fault Tolerant Computing พูดถึงความพยายามของเราที่จะทำให้ระบบคอมพิวเตอร์ยังคงให้บริการได้ตามที่คาดหวัง แม้ว่าข้างในระบบจะมีสิ่งที่ผิดปกติเกิดขึ้น สังเกตนะครับว่า ผมใช้คำว่า "ให้บริการได้ตามที่คาดหวัง" ไม่ใช่ "ไม่มีความผิดปกติเลย" นี่คือหัวใจของวิชาเลย เพราะข้อเท็จจริงพื้นฐานที่สุดของสาขานี้คือ ฮาร์ดแวร์ ซอฟต์แวร์ และเครือข่าย ไม่มีทางปลอดจากความผิดพลาดได้ทั้งหมด เราจึงต้องยอมรับว่าความผิดพลาดจะเกิดขึ้น แล้วออกแบบระบบให้อยู่รอดกับมันให้ได้

ยกตัวอย่างที่ชัด ๆ ครับ ถ้าคอมพิวเตอร์ในระบบนำทางของเครื่องบินเกิดคำนวณผิดพลาดชั่วขณะหนึ่งเพราะรังสีคอสมิกวิ่งผ่านหน่วยความจำ ถ้าระบบไม่มีกลไกป้องกันเลย ผลลัพธ์ที่ผิดก็จะไหลไปสู่การตัดสินใจของนักบินและอาจกลายเป็นอุบัติเหตุ แต่ถ้าเรามีการทำสำเนาสองสามชุดแล้วเปรียบเทียบกัน หรือมีรหัสตรวจสอบข้อผิดพลาดคอยจับ เราก็อาจตรวจจับได้ทันทีหรือแม้แต่แก้ไขข้อผิดพลาดนั้นโดยที่ผู้ใช้ไม่รู้ตัวด้วยซ้ำ นี่คือสิ่งที่วิชานี้สอน

## ขอบเขตข้อสอบของเรา

ก่อนอื่นผมขอระบุขอบเขตให้ชัดเจนก่อนนะครับ จากตารางเรียนในสไลด์และสไลด์สุดท้ายของบทเรียน ข้อสอบที่เรากำลังติวนี้เป็นข้อสอบกลางภาค ใช้เวลาสามชั่วโมง และเป็นข้อสอบแบบ **open-book, open-notes** คือเปิดให้ใช้หนังสือ เปิดให้ใช้โน้ต และเปิดให้ใช้อินเทอร์เน็ตได้ เนื้อหาที่ออกคือ "all about Fault Tolerant Computing" ซึ่งหมายถึงตั้งแต่บท FTC01 จนถึง FTC07

ส่วนบทเรียนที่ชื่อ TDC ย่อมาจาก Testing Digital Circuits นั้นจัดอยู่ในช่วงหลังสอบกลางภาค จึงไม่ออกในข้อสอบครั้งนี้ เราจึงไม่ต้องติวบทนั้นสำหรับการสอบนี้ แต่ในสคริปต์นี้ผมจะยังคงกล่าวถึงมันไว้เล็กน้อย เพื่อให้คุณเห็นภาพว่ามันต่อยอดจากส่วนไหน

เพราะสอบเป็นแบบเปิดโน้ต สิ่งที่คุณต้องทำให้ได้ไม่ใช่การท่องจำทุกอย่างแบบปิดหนังสือ แต่คือการเข้าใจให้พอที่จะ "จำแนกโจทย์" ได้ว่าโจทย์แต่ละข้อกำลังถามเรื่องอะไร แล้วรู้ว่าจะเปิดโน้ตไปหาข้อมูลส่วนไหน และต้องใช้สูตรหรือขั้นตอนอะไร นั่นคือเป้าหมายที่แท้จริงของสคริปต์นี้

## แผนที่รายวิชา: เจ็ดบทที่เล่าเรื่องเดียว

หัวใจที่ทำให้วิชานี้อ่านง่ายขึ้นมากคือความจริงว่า สไลด์ทั้งเจ็ดชุดไม่ได้เป็นเจ็ดหัวข้อที่แยกขาดจากกัน แต่มันคือเรื่องเดียวกันที่ถูกโจมตีในระดับลึกขึ้นเรื่อย ๆ โดยมีแกนกลางเป็นแนวคิดสามคำที่เราจะเจอตลอด นั่นคือ fault, error และ failure รวมถึงคำถามว่ามีวิธีอะไรบ้างในการรับมือกับมัน

บทที่หนึ่งคือ FTC01 Dependable Computing บทนี้วางรากฐานทางคำศัพท์และแผนที่ทั้งหมดของวิชา เราจะได้รู้จักคำว่า dependability ซึ่งหมายถึงความไว้วางใจได้ของระบบ และเราจะได้รู้จักกรอบคิดที่บอกว่าความไว้วางใจได้นี้ประกอบด้วยสามส่วน ได้แก่ attributes ซึ่งคือคุณสมบัติที่เราอยากให้ระบบมี, means ซึ่งคือวิธีการที่เราใช้สร้างคุณสมบัติเหล่านั้น, และ threats ซึ่งคือสิ่งที่อาจทำให้ระบบสูญเสียคุณสมบัติเหล่านั้น

ในบทนี้เราจะได้รู้จักสายพานสำคัญที่เราจะใช้ตลอดวิชา นั่นคือ สายพานจาก fault ไป error ไป failure พร้อมทั้งคำนิยามของแต่ละตัว และเราจะได้รู้จักวิธีการจัดการกับ fault ทั้งสี่แบบ ได้แก่ fault prevention, fault tolerance, fault removal และ fault forecasting

บทที่สองคือ FTC02 Fault Tolerant Systems บทนี้เป็นด้านปริมาณของวิชา เราจะได้เรียนเรื่อง failure rate, reliability, availability, ค่า MTTF และ MTTR รวมถึงวิธีคำนวณความน่าเชื่อถือของระบบที่มีการต่อชิ้นส่วนแบบต่าง ๆ ทั้งแบบ series, parallel และแบบที่ซับซ้อนขึ้นอย่าง bridge network ต่อด้วยเรื่อง redundancy รูปแบบต่าง ๆ, RAID, TMR, ระบบ Space Shuttle และ software fault tolerance

บทที่สามคือ FTC03 Byzantine Fault Tolerance บทนี้เป็นด้านระบบกระจาย เราจะได้เรียนเรื่อง process group, ปัญหา Byzantine Generals, ขั้นตอนวิธี Oral Message, กฎสำคัญที่ว่า n ต้องมากกว่าหรือเท่ากับ 3m+1, แนวคิด practical BFT และ blockchain และท้ายที่สุดคือการสื่อสารระหว่าง client กับ server ที่เชื่อถือได้

บทที่สี่คือ FTC04 Rollback Recovery บทนี้ว่าด้วยการย้อนระบบกลับสู่สภาพดีหลังเกิดความผิดพลาด เราจะได้รู้จัก checkpointing, แนวคิด consistent cut และ recovery line, ปัญหา domino effect และ livelock, ประเภทของ message ต่าง ๆ และเทคนิค recovery ในตระกูลใหญ่ ๆ ได้แก่ coordinated, uncoordinated, communication-induced และ log-based

บทที่ห้าคือ FTC05 Coding Theory บทนี้เป็นบทที่ยาวที่สุดและมีคณิตศาสตร์มากที่สุด เราจะได้เรียนเรื่อง Hamming distance และ Hamming weight, สัญกรณ์ (n,M,d) code, กฎที่บอกว่า code หนึ่ง ๆ ตรวจจับหรือแก้ไขข้อผิดพลาดได้กี่บิต, linear code และ cyclic code, generator polynomial, การ encode cyclic code ด้วยการหารพหุนามแบบยาว และตระกูลรหัสตรวจข้อผิดพลาดต่าง ๆ เช่น overlapped parity, checksum, residue code, m-of-n code, Berger code และ dual rail code

บทที่หกคือ FTC06 Self-Checking Circuits บทนี้คือการนำรหัสตรวจข้อผิดพลาดจากบทที่ห้ามาสร้างเป็นวงจรฮาร์ดแวร์ที่ตรวจสอบตัวเองได้ เราจะได้เรียนคุณสมบัติสำคัญสี่ห้าอย่าง ได้แก่ Fault Secure, Self Testing, Totally Self Checking และ Strongly Fault Secure รวมถึงแนวคิด Error Secure และ Code Disjoint ตลอดจนการออกแบบตัวตรวจที่เรียกว่า checker

บทที่เจ็ดคือ FTC07 Fault Masking บทนี้ว่าด้วยการทำให้ความล้มเหลวหายไปโดยไม่ต้องวินิจฉัยเลย เราจะได้เรียนเรื่องการบังความผิดพลาดโดยธรรมชาติของวงจรลอจิก, quadded logic, การคำนวณความน่าเชื่อถือของเครือข่ายที่ไม่ใช่ series-parallel, TMR แบบ voter สมบูรณ์และไม่สมบูรณ์, NMR, standby และ hybrid redundancy, alternating logic, time redundancy และระบบที่เรียกว่า fail-safe

อยากให้สังเกตความเชื่อมโยงระหว่างบทไว้ตรงนี้นะครับ รหัสหรือ code เป็นเสมือนสะพานเชื่อมสามบทเข้าด้วยกัน FTC05 เป็นบทที่ออกแบบรหัส FTC06 เป็นบทที่สร้างวงจรล้อมรอบรหัสนั้น และ FTC07 เป็นบทที่ใช้ redundancy เพื่อบังสิ่งที่ตรวจไม่เจอ ส่วนคณิตศาสตร์เรื่องความน่าเชื่อถือที่เราจะเรียนใน FTC02 นั้นจะกลับมาเกือบทั้งดุ้นอีกครั้งใน FTC07 ภายใต้หัวข้อ combinatorial modelling และในทางกลับกัน เนื้อหาเรื่อง Byzantine และ recovery ใน FTC03 และ FTC04 ก็คือรูปแบบของระบบกระจายของสายพาน fault ไป error ไป failure เดียวกันนั่นเอง

ดังนั้นถ้าคุณเข้าใจสายพาน fault ไป error ไป failure และเข้าใจวิธีการจัดการ fault ทั้งสี่แบบได้ดี คุณจะสามารถแขวนข้อเท็จจริงเกือบทั้งหมดของวิชานี้ไว้บนโครงเดียวนี้ได้ และเมื่อเจอโจทย์ในห้องสอบ คุณก็จะรู้ว่ากำลังอยู่ตรงไหนของแผนที่

## วิธีใช้สคริปต์นี้ให้เกิดประโยชน์สูงสุด

ผมแนะนำให้เริ่มอ่านบทที่หนึ่งและบทที่สองก่อนครับ ด้วยเหตุผลว่า คำศัพท์และสูตรเกี่ยวกับความน่าเชื่อถือในสองบทนี้เป็นหินรับน้ำหนักของทุกอย่างที่เหลือ ถ้าคุณเข้าใจสองบทนี้ดี การอ่านบทที่เหลือจะลื่นขึ้นมาก

จากนั้นจึงไล่ต่อตั้งแต่บทที่สามไปจนถึงบทที่เจ็ด และปิดท้ายด้วยบทที่แปด ซึ่งเป็นบทซ้อมโจทย์ ผมจะรวบรวมโจทย์จากข้อสอบเก่าที่จดจำมาไว้ในนั้น พร้อมทั้งแผ่นสูตรที่อ่านออกเสียงได้ และการตรวจสอบว่ามีหัวข้อใดที่ผมยังไม่ได้ครอบคลุม

เวลาอ่าน ขอให้อ่านออกเสียงจริง ๆ ครับ เพราะสคริปต์นี้เขียนมาเพื่อให้พูดได้ ไม่ใช่เพื่ออ่านในใจ ทุกประโยคเป็นประโยคสมบูรณ์ มีคำเชื่อมที่ทำให้เรื่องไหลต่อได้ และอธิบายสูตรเป็นคำพูด ถ้าคุณสะดุดตรงไหน นั่นอาจเป็นสัญญาณว่าจุดนั้นคุณยังไม่เข้าใจจริง ลองกลับไปอ่านซ้ำช้า ๆ จนกว่าจะอ่านได้ลื่น

สุดท้ายนี้ ผมอยากย้ำเรื่องความซื่อสัตย์ต่อแหล่งข้อมูลครับ เนื้อหาทั้งหมดในสคริปต์นี้อ้างอิงจากสไลด์บรรยาย จากใบการบ้านและใบแบบฝึกหัด และจากข้อสอบเก่าที่ถูกจดจำมาเพียงฉบับเดียว ซึ่งฉบับนั้นไม่ครบถ้วนและจดจากความจำ จึงใช้เป็นแนวทางว่าเนื้อหาส่วนไหนถูกเน้นได้ แต่ไม่ใช่การรับประกันว่าโจทย์จะออกแบบนั้น จุดไหนที่ผมต้องตีความหรืออธิบายเกินกว่าที่สไลด์บอก ผมจะบอกคุณตรง ๆ ว่าเป็นการตีความ ไม่ใช่เนื้อหาทางการ

เอาละครับ เราเริ่มกันที่บทที่หนึ่งได้เลย
